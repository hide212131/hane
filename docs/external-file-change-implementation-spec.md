# 外部変更の自動再読込と未保存編集の競合保護

要求・受入条件の正本: [Issue #653](https://github.com/hide212131/hane/issues/653)。
本書は設計案であり、製品実装・検証完了の記録ではない。設計PRの採用だけではIssueを閉じない。

## 1. 目的と利用者の操作

別端末・別アプリが同じファイルを保存したとき、未保存編集がなければ最新内容に自動更新する。未保存編集があれば手元の内容を守り、外部変更を知らせて解消方法を選べるようにする。自動マージや共同編集は行わない。

| 状態・操作 | 動作 |
|---|---|
| 未保存編集なし、外部で本文が更新された | 背景で読み、受理条件を確認して自動再読込する。フォーカスを奪わない。 |
| 未保存編集あり、外部で本文が更新された | 本文・undo/redo・復旧用draftを維持。「外部で変更されました」を文書に紐付く非モーダルの案内で表示する。 |
| IME変換中／保存・rename処理中 | 自動置換を延期する。処理終了後に最新の文書状態とディスクを再確認する。 |
| 競合中に通常保存／自動保存 | 外部内容を上書きせず、解消操作を案内する。Ctrl/Cmd+Sの繰返しを上書き承認と扱わない。 |
| 「差分を確認」 | 左にディスク版、右に編集中版の読取専用比較を表示する。比較を開くだけでは文書を置換しない。 |
| 「ディスクの内容を読み直す」 | 未保存内容が失われる旨を確認し、承認対象がまだ最新なら再読込する。取消時は維持する。 |
| 「名前を付けて保存」 | 別ファイルへ手元の内容を保存する。同一ファイル・同一実体へ戻る指定は競合解消を迂回しない。既存の別ファイルを置換する場合も、その対象への明示確認を要する。 |
| 「この内容で上書き」 | 手元の内容でディスク版を置き換える旨を明示して確認する。承認対象を再確認してから保存する。 |
| ファイル消失・読込不可・監視失敗 | 本文を残し、原因に応じた案内と再試行／別名保存を提示する。空文書への置換や成功表示をしない。 |

通知は繰返し重複表示せず、非アクティブ文書にはタブの状態表示と切替時の案内を用意する。競合を発見した文書のID・パスを保持し、別タブの保存・再読込へ誤接続しない。文書を閉じる際も競合を通常の保存成功扱いにしない。

作業フォルダ内と、作業フォルダを使わず単独で開いた保存済みファイルを対象にする。名前のない新規文書は外部監視対象にしない。別端末からの変更がローカルのファイルシステムで観測可能になった時点から扱う。クラウド同期制御、全共有方式の通知保証、自動マージ、排他ロック、永続履歴（#592）は対象外とする。

## 3. 状態の所有と不変条件

状態の正本は文書session側に置き、Viewは通知・操作・背景I/Oのadapterとする。具体的な型名は実装PRで確定するが、次の情報は混同しない。

- **受理済みbaseline**: 最後に正常に読み込んだ／保存したディスク内容の識別と内容fingerprint。検知しただけの外部stampでは更新しない。
- **観測した外部版**: 背景確認で読めたディスク内容と、その版を識別する情報。編集中の本文とは別に保持する。
- **再確認中／変更あり／競合／消失／確認失敗**: dirtyや保存処理中とは直交する文書別状態。`unknown`を変更なしにしない。
- **操作のidentity**: session ID、document instance/generation、workspace epoch、現在のpath identity、要求sequence、開始時revisionを結び付ける。単なる同一パスやrevision番号の一致だけで受理しない。
- **解消の承認**: 比較対象の外部版と手元revision、操作種別へ紐付く一回限りの承認。遅延・タブ切替・再変更で別内容に流用しない。

守る条件:

1. 外部変更の通知やstamp確認だけで本文・saved revision・baselineを更新しない。
2. 未保存内容またはIME変換を自動再読込で破棄しない。比較表示・読込失敗・取消でも本文と履歴を維持する。
3. 読込開始時だけでなく結果受理時にもdirty、revision、文書instance、パス、要求の最新性、IME、保存・rename状態を確認する。
4. 保存は既存slotで直列化し、競合中のpending通常保存・自動保存を強制保存へ昇格しない。新しい外部版を検出したら古い承認を無効にする。
5. 再読込が正常に受理されて初めてbaselineとsaved revisionを同じ版へ進める。文書置換時には解析・描画・位置情報・AI選択等の旧文書由来の結果も失効させる。
6. アプリ自身の正常保存の通知は、実際に保存した版と照合して重複処理を避ける。その直後の他者の変更まで自己保存として無視しない。

## 4. 検知と背景I/O

### 4.1 監視の開始・終了

OS通知を手掛かりとして、開いている対象文書だけの内容確認を背景で起動する。一覧更新のために未オープン文書を読んだり、クラウド本文のダウンロードを誘発したりしない。

作業フォルダ内では既存watcherの通知を利用し、同じrootへ不要な監視を二重登録しない。単独ファイルでは親ディレクトリを監視し、atomic saveによる同名ファイルの置換も拾う。親監視は必要に応じて共有し、文書close・rename・フォルダ切替・終了時に参照と監視を解放する。旧通知は旧identityに閉じ込める。

監視登録後に初回確認を行い、その間の通知を集約して再確認する。通知集中時は文書あたり一つの確認jobと再確認pendingにまとめ、連続更新でも一定間隔で最新状態を確認できるようにする。UI threadでファイル内容の読込・比較・hash計算を行わない。

通知欠落・overflow・監視エラー時は監視を復旧し、開いている文書を再確認する。アプリ復帰時にも開いている文書を確認する。通常経路に無変更時の定期全走査は置かない。監視できない場合は自動更新の保証がないことと手動再確認を表示する。ネットワーク共有ではOS通知の到達可否を区別し、全共有方式への即時性を保証しない。

### 4.2 内容確認

mtime/sizeは安価な手掛かりに留め、通知が来た対象や復帰時・保存前の確認では同一stampでも内容を確認する。baselineのfingerprintは読込／保存した同じbytesから作り、改行・BOM等の既存保存形式の契約を維持する。使用するfingerprint方式とメモリ上限は実装PRで選定し、単なるmtime一致で変更なしと判定しない。

読込前後のhandleとpathの同一性・metadataを確認し、atomic置換や読込途中の変更は再試行へ回す。既存の `ReadFile` のhandle/path stamp確認を参考にするが、stampだけで同サイズ同mtimeの置換を見逃さないようOSのfile identityと内容確認を組み合わせる。連続変更で整合する版を取得できない場合は確認中または失敗とし、混在した本文を受理しない。再試行は上限を設けて入力を妨げない。

### 4.3 結果の適用

確認した外部版がbaselineと同一なら、競合が解消したかを再評価する。外部版と手元が完全に同一の場合も内容一致を確認して状態を整合させ、stampだけでdirtyを消さない。

異なる版なら、受理時に未編集・IMEなし・I/O競合なしである文書だけを再読込する。開始後に入力された場合は自動置換を中止し、最新の手元を保持して競合へ移る。非アクティブ文書の更新でactive sessionを切り替えない。

正常な自動再読込は新しい文書generationの境界とし、旧本文のundo/redoをそのまま新本文へ再生しない。新本文をcleanな基準として履歴を初期化し、古いdraft writeが後着して新しい復旧内容を置換しないよう既存draftの所有・順序を更新する。永続履歴は追加しない。

表示は変更前の表示先頭・カーソル・選択を論理位置で復元し、範囲外を有効な文字境界へ丸める。行の削除等で同一位置を保持できない場合は近傍へ移す。無条件に文書先頭へ戻したり、別文書へフォーカスを移したりしない。

## 5. 競合解消と保存

比較画面はディスク版と手元版のsnapshotを固定して表示し、それぞれの版を保持する。比較中にどちらかが変われば「内容が更新されました」と表示して再比較を促す。古い比較から再読込・上書きを実行しない。

破棄を伴う再読込の確認は「未保存の編集を破棄して、ディスクの内容を読み直しますか」と対象ファイルを示す。承認後も文書revisionと外部版を再確認し、変更されていれば再承認へ戻す。安全な新本文を取得・受理できるまで現在の本文・履歴・draftを破棄しない。

上書きは「ディスク側の変更を、この文書の内容で上書きしますか」と示す専用操作にする。通常保存・自動保存・ショートカットの再操作とは区別する。承認した手元revisionと外部版を保存jobに固定し、実行直前にも確認する。確認後に新しい入力があった場合、古い承認で新しい内容を書かず再確認する。

保存前の確認はwatcherの通知到達に依存させない。競合未検知でもbaselineと実体の内容を確認する。別名保存で同一実体を選んだ場合もこの保護を適用する。削除済みの元パスへの通常保存で黙って再作成せず、再作成の明示確認または別名保存へ進む。

外部プロセスと共有ファイルシステム全体の原子的compare-and-swapは既存のstamp確認とatomic renameだけでは保証できない。実装では、読込／確認／書込／置換の境界に失敗・競合注入を行い、OSで使用可能な条件付き更新の範囲と残る競合窓を記録する。Hane内部の直列化を他端末との排他保証と説明しない。検出した不一致・不明状態では保存を拒否する。常に同時書込を無損失に統合できる機能は本Issueの対象外である。

失敗時は保存済みと表示せず、手元とdraftを維持する。上書き承認を自動再試行や次の保存へ持ち越さない。別名保存成功後は新しい保存先をbaselineとし、元の監視・競合状態を解放する。

## 6. 実装範囲と進め方

| 領域 | 変更の責務 |
|---|---|
| `crates/session/src/session.rs` / `identity.rs` | baseline・外部版・競合と解消承認、reload要求／受理、文書寿命、保存前条件。`apply_file_event` による先行stamp更新を整理する。 |
| `crates/session/src/service.rs` | 背景で利用する整合読込・内容fingerprint・保存直前の再確認。同期traitと既存保存形式を維持する。 |
| `crates/session/src/watch.rs` | 既存通知の再利用。単独ファイルの親監視が必要な部分に限って拡張する。 |
| `crates/ui/src/view/folder_watch.rs` とファイルopen/save adapter | watcher通知と開いている文書確認の接続、単独監視、再確認jobの集約、identityでの結果受理。 |
| `crates/ui/src/view/footer.rs` と文書通知・比較UI | 文書別通知、差分表示と明示的な解消操作。現在の保存案内を実際の操作契約に合わせる。 |
| 既存draft／IME／文書描画の接続 | 再読込時のgeneration境界、遅延draft拒否、IME保護、位置復元。規則を新旧両経路へ複製しない。 |

まず#309等との共有契約と変更前の保存・再読込挙動を記録し、必要な局所整理を独立して受け入れる。その後、session/I/Oの保護とテスト、監視接続、自動再読込、競合UIを一貫して実装する。内部部品だけの中間PRではIssueを完了扱いにしない。大きな文書・複数タブで変更前後の入力応答、背景確認時間、保持メモリを比較し、fingerprint／比較snapshotの上限と解放を確認する。

## 7. 受入検証表

以下は実装後に行う計画であり、本書で実施済みとはしない。遅延・失敗を注入したsession/serviceテストとGUIイベントテストを組み合わせる。

| ID | 条件・操作 | 確認する結果 |
|---|---|---|
| T01 | 作業フォルダ内／単独ファイル、active／inactive、未編集時に外部保存 | 最新本文へ更新しcleanを維持。active・フォーカス・表示位置を保つ。 |
| T02 | 未保存編集・undo/redo・draftありで外部保存 | 自動置換なし。非モーダル通知。通常保存／自動保存／連続保存でも外部版を守る。 |
| T03 | 読込開始後に入力／IME開始／save／rename | 古い結果を適用しない。IME確定・取消後に最新条件で再確認する。 |
| T04 | 比較・再読込確認・上書き確認の後に手元または外部が再変更 | 古い承認を拒否し再比較／再確認する。取消・失敗で内容を失わない。 |
| T05 | 同サイズ同mtime、atomic置換、自己保存通知の直後の外部保存 | 内容差を検出。自己保存だけを無害化し、その後の外部版を無視しない。 |
| T06 | 重複／集中通知、通知欠落、overflow、監視エラー、アプリ復帰 | 集約・有界再試行・復旧・再確認。未オープン本文は読まない。 |
| T07 | close後の遅延結果、フォルダ切替、同パス再open、別名保存 | 旧instance/path/要求の結果を拒否し、監視を正しく解放・再接続する。 |
| T08 | 外部削除、一時的な読込拒否、非対応文字コード、壊れた読込 | 元本文を維持。正常完了や空本文にしない。黙って再作成しない。 |
| T09 | 再読込後のundo/redo・古いdraft write・遅延AI／解析結果 | 新旧文書を混在させず、復旧内容は新しい文書の版と一致する。 |
| T10 | 別名保存で同一実体／既存別ファイル、通常の別ファイル、書込失敗 | 上書き保護の迂回なし。失敗時保護、成功後のpathとbaselineが一致する。 |
| T11 | ファイル読込・保存の確認境界に外部更新を注入 | 検出可能な不一致を拒否。保証できないOS競合窓を実測範囲とともに明示する。 |
| T12 | 大きな文書・複数タブで連続保存／外部変更 | UI threadを塞がず、job・snapshotが無制限増加しない。最新の安定版へ収束する。 |

macOS／WindowsでT01、T02、T03、T04、T07、T08のfocused GUIを行い、実際のファイル内容と画面・入力結果を確認する。通常ローカルファイルへの別プロセス書込を基本とし、共有フォルダの実機確認は利用した方式・同期到達・OS通知到達を区別して記録する。OS通知受信から通常単発変更の表示反映まで概ね1秒を目標とし、大文書I/O・同期待ち・連続更新を区別し、検証では待ち時間上限を明示する。

関連session/UI tests、workspace tests、Clippyおよび両OSのCIは実装PRで対象SHAへ紐付ける。必須GUIのfail/blocked/unknownをpassとせず、復旧は既存の[GUI診断・復旧手順](gui-test-recovery.md)に従う。設計文書のみの本PRは文章・リンク・差分を確認し、製品のGUI検証を実施済みとはしない。
