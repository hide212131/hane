# ADR-0024: ローカル GUI 検証を Computer Use の承認から切り離す

## ステータス

採用方針。実装・対象 Mac での検証は未完了。

この判断を記録する文書変更だけでは、非公開リポジトリ、runner、認証情報、ワークフロー、マージ条件は変更しない。

## 日付

2026-09-07

## 背景

Hane では、GitHub の Issue や Pull Request のコメントから Claude Code が実装・修正した後に、対象コミットの実アプリをローカル Mac で検証し、結果と証拠を Pull Request に返したい。

[Issue #55 の設計上の問い](https://github.com/hide212131/hane/issues/55#issuecomment-5563072265)は、Calculator の承認を通すことではなく、この開発ループを成立させることである。同コメントでは、モバイル ChatGPT から接続したセッションでのローカル操作と、独立した Codex CLI からの操作を区別している。standalone Codex CLI `0.153.4` によるアプリ一覧取得は成功したが、Calculator の状態取得はアプリ利用の承認で停止した。別セッションの承認を引き継げることや、self-hosted runner から操作できることは実証されていない。

一方、Hane には実アプリの起動・撮影、macOS を通した入力、GPUI 内のイベント処理を確認するための部品がある。これらに合否の確認と結果の受け渡しを加える経路は、Computer Use の承認問題と別に進められる。既存部品があることと、無人の GUI 検証が成立していることは同じではない。

## 決定

### 目的と操作手段を分ける

自動検証の主経路は、事前に決めたシナリオに従って Hane を起動・操作し、実際の結果を確認する Hane 専用の検証コマンドとする。Computer Use は必須条件にしない。対話的な調査で利用することは妨げないが、他のセッションの承認を再利用できることを前提にせず、安全設定を緩めて成立させない。

「入力命令を送れた」「画像を取得できた」だけでは、対象機能を検証したことにしない。保存内容、状態の変化、必要な画面上の結果まで確認する。GPUI 内のイベントテスト、macOS を通した実アプリの操作、画像の確認は、それぞれが確かめられる範囲を明示する。

### Mac に仕事を渡す設定を、公開リポジトリから分ける

Mac の self-hosted runner は、Hane 本体の公開リポジトリではなく、検証を制御する普通の非公開リポジトリに登録する。名前の候補は `hide212131/hane-gui-ci` とする。作成済みであることや、この名前で運用していることを意味しない。

Hane 本体、テストの意図、公開できる検証部品、設計の正本は `hane` に残す。非公開側には、実行依頼を受けるワークフロー、承認条件、信頼する検証手順の版、結果を回収する処理を置く。Hane 本体を二重管理しない。

分離する理由は、検証方法を秘密にするためではない。「Hane に変更を提案する権限」と「Mac に処理を実行させる権限」を分けるためである。GitHub は公開リポジトリでの self-hosted runner 利用を強く警告しており、リポジトリ単位の runner は一つのリポジトリに専用化できる。[GitHub の説明](https://docs.github.com/en/actions/concepts/runners/self-hosted-runners)と[安全上の注意](https://docs.github.com/en/actions/reference/security/secure-use#hardening-for-self-hosted-runners)を参照する。

ただし、非公開リポジトリは、取得した Pull Request のコードを安全にする仕組みではない。ビルドや実行による侵害、同じユーザーの認証情報へのアクセス、実行後の影響が残る危険は別に扱う。初期運用は、人が exact head SHA を確認・承認した同一リポジトリ内の変更に限り、個人データや不要な認証情報を持たない専用 OS ユーザーで行う。任意の外部コードを個人用 Mac で無人実行できるという安全性は主張しない。

### 実行・報告・判断の権限を分ける

Mac は検証と証拠の生成を担当し、Hane のコード修正、レビューの上書き、マージを行わない。GitHub 側の信頼する処理が依頼と結果を照合し、Pull Request への報告を行う。報告用の書き込み認証情報を、検証対象をビルド・実行する Mac に渡さない。

結果は `pass` / `fail` / `blocked` を維持する。検証対象の head SHA と実行世代を記録し、古い結果を現在の変更の成功として使わない。Mac が起動できない場合の待ち時間の上限も GitHub 側で管理する。必要な検証を完了できなければ成功にせず停止する。

[ADR-0023](0023-ai-agent-development-workflow.md)の **Claude = implementer / Codex = reviewer / Copilot = judge** は変えない。Local GUI validator は検証専用の独立した役割であり、最終判断とマージ条件は既存の全体設計に従う。

### AI による画像確認は、操作の後に分ける

必要な場合は、保存したテスト画像と観点を、画像を扱えるエージェントに渡す。候補は Codex CLI の画像入力であり、Computer Use を使わせることとは別である。認証情報を持つ画像確認環境と、Pull Request のコードを実行する環境を分ける。OpenAI API キーを必須にしない方針を維持するが、固定した CLI 版と認証経路での動作は別途実証する。

画像からは確認できない入力・保存・日本語変換の正しさを、AI の判断で補ったことにはしない。初期導入では画像の保存と人による確認を先に成立させ、AI による画像確認を自動検証の着手条件にしない。

## 採用しない案と理由

| 案 | 今回採用しない理由 |
| --- | --- |
| standalone Codex CLI が既存の Computer Use 承認を引き継ぐことを前提にする | 実証されておらず、目的である Hane の検証全体が承認問題で止まるため。将来の改善を否定するものではない。 |
| 公開 `hane` に個人用 Mac の runner を直接登録する | 公開側の変更提案と、Mac を動かす権限の分離が弱くなるため。ラベルは安全な隔離の代わりにならない。 |
| GPUI 内のテストだけで実アプリの GUI 検証を完了とする | OS の入力経路、日本語入力、実際の描画などの確認が残るため。内部テスト自体は継続して使う。 |
| AI の画像判断だけで合否を出す | 保存内容や入力の経路を画像だけで証明できず、再現できる検証結果が不足するため。 |
| 最初から独自の常駐テストエージェントを開発する | まず既存の runner と検証部品で目的を満たせるか確認する。独自の実行基盤を保守する判断は、必要性が判明してから行う。 |

## 結果と引き受ける制約

Computer Use の承認問題と、Hane の自動検証の実装を切り離せる。失敗が製品の問題なのか、実行環境の問題なのかも区別しやすくなる。一方で、シナリオと合否確認の保守、Mac のログイン状態・権限の管理、非公開側の認証・更新作業は必要になる。

最初から完全無人運用を約束しない。ログインした Terminal での起動・撮影、同じユーザーの runner、常駐起動した runner の順に実証する。初期の手動承認を外す判断や、対象コードの範囲を広げる判断は、この設計を更新してから行う。

## 文書の役割

この ADR は採用理由と変更しない原則を残す。[Local GUI validation 設計](../local-gui-validation.md)に構成、依頼・結果の契約、権限、段階的な実装順序を記す。[全体の開発ワークフロー](../agentic-development-workflow.md)は、引き続きエージェント間の役割と進行条件の正本とする。

Issue #55 は進捗と実験結果を追跡する場所とし、長い設計説明を重複して置かない。設計を変えるときは、まずリポジトリ内の文書を変更する。
