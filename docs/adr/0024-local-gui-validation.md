# ADR-0024: GUI 検証を Computer Use の承認から切り離し、hosted macOS を優先する

## ステータス

採用。2026-09-09 に GitHub-hosted macOS 優先へ更新。起動・撮影は実証済み。操作シナリオと final judge / merge gate の接続は未完了。

この判断を記録する文書変更だけでは、非公開リポジトリ、runner、認証情報、ワークフロー、マージ条件は変更しない。

## 日付

2026-09-07（2026-09-09 更新）

## 背景

Hane では、GitHub の Issue や Pull Request のコメントから Claude Code が実装・修正した後に、対象コミットの実アプリをローカル Mac で検証し、結果と証拠を Pull Request に返したい。

[Issue #55 の設計上の問い](https://github.com/hide212131/hane/issues/55#issuecomment-5563072265)は、Calculator の承認を通すことではなく、この開発ループを成立させることである。同コメントでは、モバイル ChatGPT から接続したセッションでのローカル操作と、独立した Codex CLI からの操作を区別している。standalone Codex CLI `0.153.4` によるアプリ一覧取得は成功したが、Calculator の状態取得はアプリ利用の承認で停止した。別セッションの承認を引き継げることや、self-hosted runner から操作できることは実証されていない。

一方、Hane には実アプリの起動・撮影、macOS を通した入力、GPUI 内のイベント処理を確認するための部品がある。これらに合否の確認と結果の受け渡しを加える経路は、Computer Use の承認問題と別に進められる。既存部品があることと、無人の GUI 検証が成立していることは同じではない。

## 決定

### 目的と操作手段を分ける

自動検証の主経路は、事前に決めたシナリオに従って Hane を起動・操作し、実際の結果を確認する Hane 専用の検証コマンドとする。Computer Use は必須条件にしない。対話的な調査で利用することは妨げないが、他のセッションの承認を再利用できることを前提にせず、安全設定を緩めて成立させない。

「入力命令を送れた」「画像を取得できた」だけでは、対象機能を検証したことにしない。保存内容、状態の変化、必要な画面上の結果まで確認する。GPUI 内のイベントテスト、macOS を通した実アプリの操作、画像の確認は、それぞれが確かめられる範囲を明示する。

### GitHub-hosted macOS を最初に使う

標準の GitHub-hosted macOS runner を優先する。検証用にローカルの専用 OS ユーザー、self-hosted runner、非公開制御リポジトリを作ることを必須条件にしない。

[実験 run 34254547035](https://github.com/hide212131/hane/actions/runs/34254547035) では、標準 `macos-15`（macOS 15.7.9 / ARM64）で、対象 SHA の build / launch / window discovery / capture / cleanup がすべて成功し、Hane の見出しと日本語本文の画像を確認した。[保存した証拠](../history/gui-validation/2026-09-09-hosted-launch/README.md)に対象と手順の SHA、環境、画像、範囲を記録する。GPU性能、日本語IMEや全操作の成功をこの一例から推測しない。

GitHub の [runner image 設定](https://github.com/actions/runner-images/blob/57fdccbc4a47d85e23cc79eaeb63cb8ae0e997b5/images/macos/scripts/build/configure-tccdb-macos.sh)には画面取得・アクセシビリティ等の設定がある。設定の存在だけを成功の根拠にせず、実際の Hane の操作・保存内容・画像で確かめる。TCC DB や安全設定を変更して成功させる運用にはしない。

検証手順は信頼した版から、アプリは対象 PR の exact head SHA から別々に取得する。hosted 実行ジョブは書き込み認証情報や個人文書を持たず、checkout の認証情報を残さない。結果受領と書き込みは別の信頼するジョブで行う。対象は引き続き許可した作成者の same-repository PR とし、外部 PR を無条件実行しない。

### hosted で不足する操作だけローカルで補う

個人用エディタの検証であるため、ユーザーが確認したコードと操作を通常のログインアカウントで実行する構成も認める。専用アカウントや非公開リポジトリは無人の常駐実行・運用を分離する選択肢であり、変更不能な必須条件ではない。

ローカルで必要な場合は、実行ごとにテスト文書・設定・証拠を一時領域へ分け、対象プロセスだけを操作・終了する。普段の作業と入力が競合する時間には実行しない。入力方式など変更した状態を復元し、画面に個人パスが含まれる場合はそのまま公開しない。通常アカウントを使うことは任意の外部コードを安全に実行できるという意味ではない。

2026-09-07 の非公開制御 repo / 専用ユーザー必須という判断は、この hosted の実証とユーザーの方針見直しにより置き換える。既存の private repo、runner、認証情報が用意済みであるとは扱わない。

### 実行・報告・判断の権限を分ける

Mac は検証と証拠の生成を担当し、Hane のコード修正、レビューの上書き、マージを行わない。GitHub 側の信頼する処理が依頼と結果を照合し、Pull Request への報告を行う。報告用の書き込み認証情報を、検証対象をビルド・実行する Mac に渡さない。

結果は `pass` / `fail` / `blocked` を維持する。検証対象の head SHA と実行世代を記録し、古い結果を現在の変更の成功として使わない。Mac が起動できない場合の待ち時間の上限も GitHub 側で管理する。必要な検証を完了できなければ成功にせず停止する。

[ADR-0023](0023-ai-agent-development-workflow.md)の **Claude = implementer / Codex = reviewer / Copilot = judge** は変えない。GUI validator は検証専用の独立した役割であり、最終判断とマージ条件は既存の全体設計に従う。

### AI による画像確認は、操作の後に分ける

必要な場合は、保存したテスト画像と観点を、画像を扱えるエージェントに渡す。候補は Codex CLI の画像入力であり、Computer Use を使わせることとは別である。認証情報を持つ画像確認環境と、Pull Request のコードを実行する環境を分ける。OpenAI API キーを必須にしない方針を維持するが、固定した CLI 版と認証経路での動作は別途実証する。

画像からは確認できない入力・保存・日本語変換の正しさを、AI の判断で補ったことにはしない。初期導入では画像の保存と人による確認を先に成立させ、AI による画像確認を自動検証の着手条件にしない。

## 採用しない案と理由

| 案 | 今回採用しない理由 |
| --- | --- |
| standalone Codex CLI が既存の Computer Use 承認を引き継ぐことを前提にする | 実証されておらず、目的である Hane の検証全体が承認問題で止まるため。将来の改善を否定するものではない。 |
| 外部 PR を個人用 Mac で無条件実行する | hosted / local を問わず実行対象を制限する。ラベルだけで外部コードの安全性は保証できない。 |
| GPUI 内のテストだけで実アプリの GUI 検証を完了とする | OS の入力経路、日本語入力、実際の描画などの確認が残るため。内部テスト自体は継続して使う。 |
| AI の画像判断だけで合否を出す | 保存内容や入力の経路を画像だけで証明できず、再現できる検証結果が不足するため。 |
| 最初から独自の常駐テストエージェントを開発する | まず既存の runner と検証部品で目的を満たせるか確認する。独自の実行基盤を保守する判断は、必要性が判明してから行う。 |

## 結果と引き受ける制約

Computer Use の承認問題と GUI 検証を分け、使い捨て hosted runner で起動から順に実証できる。ローカルアカウントの準備を先に要求する必要がなくなった。一方、操作シナリオの保守、対象 SHA・手順の版・実行世代・証拠の照合、runner image 更新に伴う差の扱いは必要になる。

起動・撮影、OS入力と保存、undo/redo・再オープン、IME・スクロールなどを独立した結果として記録する。起動できただけで GUI 全体や Issue #44 を完了にしない。hostedで不足が実証された操作に限り、通常アカウントを含むローカル補完を検討する。
