# ADR-0031: AADW v3の限定判断をJev、実装をCodex、事実確認を検証ツールに分離する

## ステータス

設計採用（本ADRを含むPRのmergeで承認）。実装・運用切替は未実施。

現行運用は引き続き[ADR-0027](0027-aadw-v2-chatgpt-commander.md)と[Commander Policy](../aadw-command-policy.md)に従う。本ADRだけではv2を置き換えず、Jevや実行プログラムへの権限委譲も有効にならない。

## 日付と追跡先

2026-09-25。設計: [#332](https://github.com/hide212131/hane/issues/332)。実装・評価・有効化: [#333](https://github.com/hide212131/hane/issues/333)。

## 背景

v2ではChatGPT CommanderがGitHubの現在の事実を読み、次の一つのactionを選ぶ。通常の実装はClaude Codeであり、Codex実装は利用上限時の限定fallbackである。

利用者提供の記事は、生成をLuna/Sol、限定判断をJev、検証できる事実の取得をコンパイラ・テスト等へ分離する構成を提案している。TypeSafeの公式Skillは、狭い意味判断を型付きの回答として受け取り、既知の規則と実行をコード側に置く設計を示す。出典と確認範囲は[v3設計書](../agentic-development-workflow-v3.md#sources)に記す。

Haneでは、この構成を通常の実装反復へ取り入れたい。一方、保存・入力・undo/redoなどの正しさ、current head/baseに対応する検証、秘密情報の隔離は維持する。費用削減や精度向上は未実測であり、採用理由を実証済みの性能として記述しない。

## 決定

通常の限定判断と実装を自動的に反復できる、小さな開発用実行器を設計する。最初からHane製品の画面や常駐サービスに組み込まない。

| 担当 | 将来の委譲範囲 |
|---|---|
| Commander | 目的・受入条件・変更範囲・予算・検証計画を確定し、範囲変更、設計上の例外、最終受入、mergeを判断する |
| Jev | 許可された実装設定の選択、証拠の意味評価、継続・修正・追加検証・上位設定への切替・実装完了候補を判断する |
| Codex上の実装モデル | 調査、コード変更、回帰テスト追加を行う。次工程や権限を変更しない |
| 実行器・検証ツール | 実際のモデル指定、検証と差分の収集、回答の組合せ、鮮度・権限・予算の強制、履歴の記録を行う |

JevはCommanderの長い判断文を丸ごと置き換えるものではない。Choiceで許可済み選択肢から選び、Noulで受入条件ごとの裏付け等を判断する。独立した判断はまとめて問い合わせるが、同一リクエストの回答同士を参照させない。意味判断が不要な規則はモデルに聞かない。

実装完了候補とmerge可能を分ける。Jevの`COMPLETE`は最終受入への提出候補であり、必須検証の免除やmergeの許可ではない。型付き出力、確率、confidenceだけで正しさを保証しない。

## 実行方式

最初のローカル試行ではCodex App Serverを利用する設計とする。モデルと推論量を実行時の引数で指定でき、イベントを取得できるためである。記事中のLuna/Solは論理的な設定名として扱い、APIのモデルIDや利用可否を推測しない。

公式文書は自動ジョブやCIにはCodex SDKを案内している。したがってApp ServerをCIの標準実行方式と決めつけない。CI化する段階でSDK/非対話実行との適合を確認し、同じ実行契約の下で判断する。実装言語とSDK固定版は後続Issueで既存構成と照合して決める。

## 選ばなかった案

| 案 | 採用しない理由 |
|---|---|
| Commanderが毎回判断し、Jevを参考にするだけ | 観測試験には使えるが、通常の反復を委譲する到達点にならない |
| 一つのChoiceとconfidenceだけで完了・mergeする | 証拠不足、範囲逸脱、未実施検証、権限を区別できない |
| Codexの設定文だけでモデル切替を済ませる | 実際に起動したモデル・推論量を確認できる実行契約にならない |
| 汎用の状態機械・独自進行DBを復活させる | GitHubとの二重管理と運用基盤の肥大化を招く。まず一件分の限定反復で足りる |

## 影響と制約

Jev障害と実装失敗、検証不足と能力不足を区別する処理が必要になる。質問・入力・モデルの版と結果を残すことで誤判断を調べられるが、未確認の精度や費用改善は保証しない。

GitHubを進行状態の正本とする。実行履歴は監査・費用のために保存できるが、古い結果を現在の状態として再開に使わない。既存のClaude/Codex fallbackは本ADRでは変更しない。

設計書の将来仕様は、現在のCommander Policyより優先しない。有効化PRで対象範囲と例外を同Policyへ反映し、運用の判断規則を一つの正本に集約する。worker、workflow、質問定義に別々の判断規則を作らない。

## 検証・有効化

[実行計画](../aadw-v3-execution-plan.md)に従い、モデル実指定、Jev接続、観測評価、限定有効化の順に進める。実API検証、評価で決めた閾値と予算、停止・復帰試験、Commander PolicyとAGENTSの更新をそろえるまで、現行v2のまま運用する。
