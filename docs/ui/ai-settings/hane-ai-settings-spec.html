AI設定画面の仕様

表示する情報・操作の意味・状態の変化を定義します。

HANE · UI PROPOSAL 01 · 2026-09-30
これは、提示された画面と先の改善案に基づく画面・操作の提案です。現在のHaneの実装や、実際の接続状態を示すものではありません。上部の状態切り替えと「仕様を読む」は、サンプル専用の操作です。

1. 画面の役割と配置

利用者が、「いま何が有効か」「あと何が必要か」「次に何を押すか」を推測せず判断できる画面にします。現在の状態を読む場所と、設定を編集する場所を分けます。

表示領域表示・操作の定義
現在有効な設定実際に適用できた接続方法・接続先・モデル・その組み合わせでの確認結果を表示します。入力中や保存中の値では書き換えません。未設定時は、次に行う設定を案内します。
接続方法の選択「ChatGPTアカウント」「APIキー」の二択です。ラジオマークと枠で選択状態を示します。「現在の接続方法」は実際の適用状態を示し、編集上の選択とは区別します。非選択側の保存済み設定は保持して、入力欄は閉じます。入力途中で接続方法を切り替えるときは、未保存の入力を破棄する確認を挟みます。
接続の設定選択側の項目だけを表示します。すべての入力欄に常時見えるラベルを付けます。OpenAIは接続先を自動設定し、その他の接続先では接続名・URLを展開します。
応答を確認保存・適用済みの接続先とモデルを明示して、明示的な操作でテストします。未保存の変更がある間は実行できず、保存・適用または破棄を案内します。料金・利用枠と文書送信の有無はボタンの近くに示します。
保存操作画面下に固定し、未保存・適用中・適用失敗を表示します。「保存して適用」と「変更を破棄」をまとめます。変更がないときは無効にし、その理由を併記します。
診断情報内部の起動状態、バージョン、通信先、応答原文などは閉じた領域へ移します。ただし、利用を妨げる問題とその解決操作は、診断情報を開かなくても分かる場所に表示します。

2. 保存・適用・確認は別の状態として扱う

編集中の設定、保存できた設定、実際に適用できた設定を別に保持します。保存が成功しただけでは「現在有効」を更新しません。適用失敗時は、最後に適用できた設定を残し、「保存済み・未適用」と再試行を示します。

編集 → 入力を検証 → 保存 → 接続設定を適用 → 応答を確認（任意） 保存に失敗：編集中の内容を残して再試行 適用に失敗：現在の設定を維持して再試行 確認に失敗：原因と対処を表示
状態画面に表示する内容と、次の操作
初回・未設定「AI接続はまだ設定されていません」。選択した接続の入力またはログインを案内します。応答確認はできません。
未保存の変更あり「未保存の変更があります」。現在有効な設定は変えません。「保存して適用」を主操作にします。無効な値は、保存時に項目の近くへ理由を表示します。
保存中・適用中進行中の処理を表示し、重複操作を防ぎます。保存後は「保存済み・適用中」と示します。完了まで現在有効な設定を変えません。
保存済み・適用失敗現在有効な設定を残して「保存した設定を適用できませんでした」。下部に「適用を再試行」を表示します。このサンプルでは、再試行で復旧します。
適用済み・未確認「応答はまだ確認していません」。認証の前提を満たす場合に「応答を確認」を実行できます。保存だけではテストしません。
応答確認成功成功した対象と確認日時を表示します。接続先・モデル・認証情報が変わった後に、以前の成功を流用しません。
応答確認失敗理由を平易に示し、設定変更や再試行を案内します。直近の確認が失敗したのに、以前の成功を現在の結果として表示しません。
認証が必要「ログインが必要」または「APIキー未登録」。必要な操作を案内し、応答確認は無効にします。他方の接続へ勝手に切り替えません。

確認結果は、接続方法・通信先・モデル・認証情報の識別情報と結び付けます。キーそのものを履歴に残しません。表示名だけの変更では、同じ通信設定の確認結果を無効にする必要はありません。

3. 接続方法ごとの操作

ChatGPTアカウント：ログイン → モデル選択 → 保存して適用 → 必要に応じて応答確認、の順です。この提案では、ログインを接続方法の適用から分離し、ログインしただけでは有効な接続を切り替えません。ログイン状態は独立して保持し、設定の破棄ではログアウトしません。ログアウトは確認を挟み、有効な接続への影響を説明します。

APIキー：AIサービス、モデルID、APIキーを指定します。その他の接続先には、接続名とURLも必要です。「登録済みキーを維持」の操作は設けず、何もしなければ保持します。「変更」でだけ入力欄を開きます。「削除」は予約として示し、保存・適用時に確定します。登録中のキーを表示しません。

接続先の変更：登録済みのキーを異なる通信先へ自動で流用しません。新しい接続先に合うキーの登録を案内します。キー削除を明示して適用したときは「APIキー未登録」とし、再登録までAI接続を停止します。

モデル：ChatGPT側は、取得した一覧から選ぶ操作と手入力を分けます。API側は、サービスが指定するモデルIDを入力します。このサンプルの「gpt-6-luna」は提示画像にある文字列を使った表示例で、実在・提供状況・利用可能性を保証しません。一覧取得が失敗した場合は、理由と再試行、利用可能なら手入力の経路を示す必要があります。

4. 説明と操作を近づける

無効な操作には、すぐ近くで理由と次の操作を示します。未保存なら「保存・適用または破棄」、未ログインなら「ログイン」、キー未登録なら「登録して保存・適用」を案内します。エラーを画面下の一時通知だけに置きません。

保存成功は画面下で一時的に知らせ、現在の状態は固定の表示で確認できるようにします。「準備完了」「未確認」「成功」のような、対象が分からない単独の文言は避けます。

「アプリに戻る」とページ離脱では、未保存の変更がある場合に破棄の確認をします。ログイン・ログアウトは独立した操作なので、破棄で取り消されると誤解させません。狭い画面では入力項目を1列にし、ラベルや説明を切り落としません。

5. 実装前に確認すること・完了条件

実装前の確認：現在のHaneのコードは、このサンプル作成では確認していません。①既存接続を保ったままログイン準備できるか、②適用失敗時に旧設定での動作を維持できるか、③保存・適用・認証・確認結果を別々に取得できるか、を実装側で確認します。この画面が要求する振る舞いであり、既存機能の断定ではありません。

既存接続を保ったままログインできない場合は、切り替えが必要な理由と影響を事前に表示します。実際には旧接続を維持できなかったのに「現在の接続は変わりません」と表示してはいけません。

完了条件：画面を開くだけで現在の接続・モデル・確認状態が分かること。編集しても保存・適用前に現在の表示が変わらないこと。非選択側の未設定を現在の問題と誤解しないこと。通信に関わる変更後に古い成功が残らないこと。進めないときに原因と次の操作が分かることを、画面操作で確認します。

サンプルの範囲：接続方法の選択、条件に応じた入力、キーの変更・削除予約、模擬ログイン、保存と適用、適用エラーの再試行、応答確認、応答エラー、破棄確認を操作できます。実際のネットワーク通信・アカウント認証・キー保存は行いません。保存失敗やモデル一覧の取得失敗は仕様のみで、サンプルには発生操作を設けていません。
