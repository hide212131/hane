# AI設定画面の改修仕様・実装担当者向け案内

利用者が「いま何が有効か」「あと何が必要か」「次に何を押すか」を、推測せず判断できるAI設定画面に改修するための資料です。

実装の追跡先は [Issue #379](https://github.com/hide212131/hane/issues/379)、関連する実装は [PR #397](https://github.com/hide212131/hane/pull/397)、既存の詳細設計は [PR #392](https://github.com/hide212131/hane/pull/392) です。この資料の登録だけで、製品の改修完了やIssueの完了とはしません。

## 1. 最初に確認するもの

[操作できる画面仕様：hane-ai-settings-spec.html](./hane-ai-settings-spec.html) を取得し、ローカルのブラウザーで開いてください。GitHub上でソースを読むだけでなく、画面を操作して確認します。ビルドやサーバーの起動は不要です。

右上の「仕様を読む」に、画面構成、操作の意味、状態の変化、完了条件をまとめています。「表示する状態」で初回・未設定、適用済み・応答未確認、応答確認エラー、適用エラー、ChatGPT・未ログインなどを切り替えられます。

まずモデルIDを編集し、上部の「現在有効な設定」が変わらないこと、下部に未保存と表示されること、「保存して適用」の完了後に現在の設定が変わり、新しい設定の応答確認が未確認になることを試してください。

実際の通信・ログイン・キー保存・課金は行いません。実際のAPIキーは入力せず、任意のサンプル文字列を使ってください。

## 2. このHTMLの位置づけ

HTML内の説明と画面操作を、UI改修の参照仕様として扱います。詳細を別の設計書へ丸ごと複製しません。ただし、次節の既存契約との照合事項は未解決であり、HTMLの模擬動作を実装可能性の証拠にはしません。

Haneの既存の全画面設定とUI部品を使って実装してください。HTMLをアプリに埋め込む指示でも、JavaScriptの模擬処理を本番へ移植する指示でもありません。通常の設定から診断情報を分け、編集内容と実際の適用状態を分ける構成・操作を重視します。

上部の状態切り替え、「仕様を読む」、サンプルのリセット、サンプル専用の注意書きは本番画面に含めません。「一般」「エディター」の新機能も今回の対象ではありません。サンプルのモデルID、アカウント、日時、成功応答を本番の初期値や実測結果として使わないでください。

## 3. 実装前に既存の契約と照合すること

着手時にcurrent main、Issue #379、PR #392・#397の状態と対象head、関連コードを再取得してください。過去の会話やPR本文中の古い検証結果だけで判断しません。既存のAI基盤を作り直さず、今回の表示・操作変更に必要な範囲を特定します。

| 照合する点 | 実装前に確認・記録すること |
|---|---|
| ログインと接続切り替えの順序 | Issue #379の具体契約では、ログインと接続確認は保存済みのアクティブ接続に作用します。一方、HTMLは接続方法の適用前にログインを準備する提案です。両立を仮定せず、現行コードで可能な範囲と必要な変更を確認してください。切り替えが先に必要なら、その理由・影響・操作順を表示する案を示してください。 |
| 適用失敗時の旧接続 | HTMLは旧設定での動作を維持する模擬表示です。実際のruntime再起動・キー変更・削除後にも維持できるか確認してください。旧接続を維持できない場合に「現在有効」「現在の接続は維持しています」と表示してはいけません。最後の適用設定を履歴として示すことと、現在利用できることを区別します。 |
| 状態と秘密情報の扱い | 編集中・保存済み・適用済み・認証・応答確認を、実際のサービス状態からどう表示するか確認します。APIキーのKeep/Replace/Deleteは内部契約として維持しつつ、利用者には「維持」ボタンを押させません。確認結果は接続先・モデル・認証情報の識別情報に結び付け、生のキーを記録しません。 |

食い違いがある箇所は、根拠となるコードと対応案をIssueまたは実装PRへ残し、必要な設計判断を確定してから該当部分を実装してください。HTMLを黙って変更したり、見本どおりに見せるために安全条件を外したりしないでください。合意した変更はHTML内の仕様にも反映します。

Issue #379の保存後復旧、`cleanup_pending`、保存の耐久性未確認、runtime所有権、処理中の操作制限、認証情報の分離、文書をテスト送信へ添付しない条件は引き続き守ります。利用を妨げる問題は診断情報の中だけに隠しません。リファクタリングとの依存は変更が重なる範囲に限定し、[AGENTS.md](../../../AGENTS.md) と [Commander Policy](../../aadw-command-policy.md) に従って記録してください。

## 4. 確認方法と完了条件

詳細な完了条件はHTMLの「仕様を読む」第5節を参照してください。初期表示だけでなく、初回設定、接続方法の切り替え、キーの変更・削除予約、未保存と破棄、保存中・適用中、適用失敗と再試行、応答未確認・成功・失敗、ログイン・ログアウトを実際のHaneで確認します。

保存失敗とモデル一覧の取得失敗は、HTMLの説明にはありますが、サンプルに発生操作はありません。サンプルで試せる状態だけを実装・テストの対象にしないでください。日本語入力、キーボード操作、狭いウィンドウ、設定から戻る操作、背後の文書状態・undo・選択・スクロールへの影響も既存要件に沿って確認します。

実装PRには、対象head、変更点、受入条件ごとの確認結果と証拠、未確認事項を記載してください。HTMLの模擬成功を、実OAuth・実接続・製品GUIの成功証拠として扱いません。この文書追加だけでIssue #379をcloseしません。
