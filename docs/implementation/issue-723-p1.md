## 今回の範囲

設計書の採用版に従う。要点:

1. アプリ単位の自動確認 coordinator（新規 `crates/app/src/auto_update.rs`）: 起動30秒後＋6時間間隔、最終試行を `<state root>/updates/<InstallId>/auto-check.conf` に永続化して再起動をまたいで間引く。
2. 自動経路は確認→検証→自動ダウンロード→`Ready` まで連鎖させる。実行元 `OperationOrigin::{Manual, Automatic}` を導入し、自動が連鎖させるのは自分の確認で得た候補だけにする。手動経路は従来どおり `Available` で止まる。
3. `Ready` になったら、本文領域の上端に重ねる**オーバーレイ帯**で「新しいバージョン vX.Y.Z があります。再起動して更新しますか？［再起動して更新］［後で］」を表示する。座標計算には触れない。フォーカスを奪わない。
4. 「後で」は同バージョンの再表示を6時間抑制（キー: InstallId・対象・バージョン）。`Ready` 保持中は新版確認をせず、保持候補の再検証のみを行い、失敗したら案内を取り下げる。
5. 設定 `auto_update_check`（既定 true）を `settings.conf` に追加し、更新カードにトグルを置く。無効化時は自動処理だけを取り消す。
6. 自動の失敗は診断にのみ記録し、手動用のエラー文言・「最新版です」表示を出さない。trust 未設定・非対応配置では自動通信を開始しない（fail-closed 維持）。
7. 再起動は既存のガード（未保存文書・IME 等）と適用フローをそのまま使う。拒否理由は帯にも表示する。
