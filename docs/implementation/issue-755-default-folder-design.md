# Issue #755 実装設計書 — デフォルトのフォルダの表示・変更

## 概要

設定画面の「一般」に、次回の通常起動で開くデフォルトのフォルダを表示する。フォルダ選択ダイアログで選択を確定すると、その場で `store_settings` を呼び出して保存する。開いている作業フォルダやタブは維持し、新しいデフォルトは次回のパス引数なしの起動から使う。[Issue #755](https://github.com/hide212131/hane/issues/755)

設計基準は `main` の `411c8089`。設定画面の分離は PR #620 で受け入れ済みで、今回はその画面と既存の設定保存経路を使う。起動時の分岐、設定ファイル形式、作業フォルダ切り替えの契約に手を入れる先行作業は不要と判断した。[基準コミット](https://github.com/hide212131/hane/commit/411c8089cebb0f49d7a4de8dca3af533cb3ab60f) · [PR #620](https://github.com/hide212131/hane/pull/620)

## 配置と UI 文言

「一般」の「保存」の直後、アプリ更新の前に独立したカードを置く。通常起動に関わる設定を一般カテゴリの上部で見つけられるようにする。カードの余白、枠線、背景、文字色は「ファイル・フォルダーの並び順」にそろえ、操作には既存の `Button` の `ghost` スタイルを使う。

| 要素 | 文言・表示 |
|---|---|
| 項目名 | デフォルトのフォルダ |
| 補足 | 次回の通常起動時に、このフォルダを開きます。 |
| 設定済みの値 | 保存されているパス。表示幅に収まる場合は全体を表示 |
| 未設定の値 | 未設定 |
| 操作ボタン | 設定済みなら「変更…」、未設定なら「選択…」 |
| ダイアログのタイトル | デフォルトのフォルダを選択 |
| 選択ダイアログのエラー | フォルダを選択できませんでした（{error}）。 |
| 保存エラー | 既存の「設定を保存できませんでした: {error}。この起動中は反映されていますが、次回起動時に戻る可能性があります。」を再利用 |

パスはホーム配下でも `~` に置き換えず、保存されている表記を使う。長いパスは値の欄だけを一行で末尾省略し、ホバーで省略前の全体を表示する。ファイルタブの `HoverCard` を実装例とする。狭い画面では値とボタンを縦に並べ、ボタンを押せる幅を確保する。表示用文字列は描画時に作り、保存にはダイアログが返した `PathBuf` を渡す。保存済みのフォルダが移動・削除されていても、設定画面ではそのパスを表示する。

カードの操作は一つにする。`None` は既存設定の読み込みと初回起動の状態として扱い、今回の UI にクリア操作は設けない。フォルダの設定と変更は同じ操作で完結し、利用者方針に合わせてボタンを一つにできる。

## 振る舞いと理由

- **選択を確定。** `PathPromptOptions` はフォルダのみ、単一選択とする。ダイアログが開いている間は操作ボタンを無効にする。結果を受け取ったら、その時点の `self.settings.default_folder` に `Some(path)` を設定し、`store_settings` を呼んでから `cx.notify()` で表示を更新する。設定画面は開いたままとし、同じフォルダの再選択でも保存を実行する。保存に失敗した場合も、同じ操作で再試行できる。
- **現在の作業を継続。** `switch_to_work_folder` は `reset_for_work_folder_switch` を通じて、保留中の下書きを書き出した後、`SessionSet` を新しい無題セッション一つに置き換える。旧フォルダの下書き管理、サイドバーの選択・展開・ピン、タブ関連の保留状態を片付けてから、新しいフォルダの走査を始める。現在のタブを閉じる影響は保存済みの文書にも及ぶ。設定画面からはこの処理を呼ばず、編集中のタブや保存中のセッションがあってもデフォルトを変更できるようにする。初回起動の `prompt_default_work_folder` は新しい無題ウィンドウを前提としており、選択したフォルダを開く既存の動作を維持する。
- **キャンセルとダイアログ失敗。** キャンセルと空の選択結果では書き込みを行わず、エラーも表示しない。ダイアログが返したエラーは、初回選択と同じく失敗理由を伝える。設定画面の描画中は通常のフッターが表示されないため、操作したカード内に表示する。結果を受け取れなかった場合も書き込みは行わず、ビューが生存していればカード内に失敗を表示する。ビューが閉じられていれば結果を破棄する。
- **保存失敗。** 既存の一般設定と同じく、選択した値はメモリに残し、`settings_store_error` の共通表示で永続化できなかったことを伝える。同じパスを選び直すか、その後の設定保存が成功すれば永続化される。保存成功時は `store_settings` が共通エラーを解除する。
- **起動時の優先順位。** `prepare_launch` は明示パスを優先し、パス引数なしの場合にデフォルトを読む。したがって、デフォルトが A の状態で B を引数に起動すると B が開き、設定画面には A が表示される。設定画面で明示的に変更を確定したときだけ、新しい値を保存する。デフォルトが未設定、または保存済みパスがディレクトリとして使えない場合は、既存の起動時処理に従う。

## テスト計画

### 自動テスト

`crates/ui/src/view.rs` の `settings_screen_replaces_editor_and_escape_returns_to_it` と `narrow_settings_keep_general_controls_inside_the_window` の流儀に沿って、`#[gpui::test]` で実際の設定画面を描画する。新規ケースでは `EditorView::from_sessions` に `StateStores::memory()` を渡し、本番の設定ストアから隔離する。画面上の押下は `debug_bounds` と `simulate_event`、フォルダ選択の確定・キャンセルは `simulate_path_prompt_response` を使う。

| テスト名候補 | 確認すること |
|---|---|
| `general_settings_shows_the_saved_default_folder_or_unset` | ストアに値がある場合と `None` の場合で、表示に渡す値とボタン文言が正しい。狭いウィンドウに長いパスを与えても、カードと操作ボタンが画面幅内に収まる。 |
| `changing_default_folder_saves_without_replacing_open_sessions` | ボタンを押すとフォルダのみ・単一選択のダイアログが開く。選択後、ビューとストアの再読込結果の両方に新しいパスが入り、他の設定値は維持される。設定画面は開いたままで、作業ルート、タブ、アクティブセッション、未保存テキストと dirty 状態が維持される。 |
| `cancelling_default_folder_picker_preserves_the_saved_folder` | キャンセルと空の結果で、表示値、ストアおよび現在の作業ルートが変わらず、再度ダイアログを開ける。 |
| `default_folder_picker_error_keeps_the_previous_value` | 結果処理にダイアログエラーを渡すと、以前の設定値を保ったままカード内にエラーが出て、再試行できる。 |
| `default_folder_save_error_is_visible_and_same_path_can_be_retried` | このケースだけ `StateStores::new` で失敗を注入できるテスト用 `SettingsRepository` を使う。書き込み失敗時はストアに旧値が残り、画面に共通エラーが出る。同じパスを再選択し、書き込みが成功すると新しい値が保存されてエラーが消える。 |

既存の `crates/session/src/store.rs` の `settings_survive_a_store_reload` と `default_folder_is_absent_until_set` で永続形式の互換性を確認する。引数付き起動の優先順位は、アプリの起動経路を通る実機シナリオで確認する。

### 実機 GUI 確認

対象コミットの Debug ビルドを使い、一時フォルダ A・B・C と専用の `HANE_STATE_DIR` を用意する。ビルド種別、コミット SHA、実行バイナリのパス、PID、起動引数、使用した state を記録する。

1. 空の state でパス引数なしに起動し、初回ダイアログをキャンセルする。「一般」で「未設定」と「選択…」を確認する。A を選択してパス表示が更新されることを確認する。
2. 終了してパス引数なしで起動し、A が開くことを確認する。複数タブのうち一つに未保存編集を作り、設定画面を開く。「変更…」からいったんキャンセルして A の表示が続くことを確認し、次に B を確定する。同じ画面で B が表示され、エディタに戻ると作業フォルダは A のままで、タブと未保存編集が残っていることを確認する。
3. B には長いパス、日本語、空白を含むフォルダを使う。狭いウィンドウで省略表示、ホバー時のフルパス、ボタンの操作性を確認する。専用の `settings.conf` も確認し、終了前に B が保存されていることを確かめる。
4. テスト用の編集を保存して終了し、パス引数なしで再起動して B が開くことを確認する。次に終了して C をパス引数に起動し、C が開いても「一般」の表示と保存値は B のままであることを確認する。もう一度パス引数なしで起動し、B が開くことを確認する。

ネイティブダイアログは macOS と Windows の対象環境で確認する。Windows は接続済みの Windows 環境上の ChatGPT アプリから直接操作する。今回は設計のみを提示しており、コード変更、テスト実行、実機 GUI 確認は行っていない。

## 対象外

- 現在の作業フォルダを切り替える操作や、タブ・下書きの管理方法の変更
- 初回ダイアログ、外部からのファイル・フォルダオープン、設定ファイル形式の変更
