# フッタ整理・保存状態・文字数表示の実装設計

## 1. 目的と設計の位置づけ

文章を書いている途中で確認する情報と操作を、低い1行のフッタへまとめる。変更頻度の低いテーマと自動保存は一般設定へ移し、最近開いたファイルは上部のファイルメニューから開く。

利用者との合意は「フッタに保存状態・文字数と選択文字数・表示倍率・AIへの入口を置く」「滅多に変更しない項目は設定画面へ移す」である。本書はこの合意を実装可能な仕様に具体化する。文字数の定義、狭い幅での表示、保存失敗の保持方法も本書で決める。

設計日: 2026-10-21（日本時間）。調査したmainは `97c279acc063ef51ad5d5ee12af51a0edee174d2`。本書作成時点で製品変更・製品テスト・実画面検証は未実施である。設計文書の保存は製品の実装完了を意味しない。

要求と完了条件は本書を参照する機能Issueに置き、具体的な表示・処理・変更箇所は本書を正とする。今回だけの画面整理なので新しいADRは作らない。実装開始時はcurrent mainと関連作業を再確認し、本書の調査時点と区別する。

## 2. 現状と変更する範囲

現行フッタは高さ54pxで、上段24pxのメッセージと下段の操作に分かれる。通常メッセージがない場合、上段には内部の更新番号、文書のバイト数、描画時間などを表示する。下段には設定、AI、自動保存、テーマ、最近のファイルがある。最近のファイルは保存済みの履歴のうち最大3件を横に並べている。[S1][S2]

| 項目 | 今回の変更 | 再利用するもの |
| --- | --- | --- |
| フッタ | 高さ32px、1行、横スクロールなしにする | 現在のテーマ色、ボタン部品、エディタ列の幅計算 |
| 保存状態 | 現在の文書から導き、保存失敗は文書ごとに保持する | `DocumentSession`、保存結果、既存の文書識別 |
| 文字数 | 全体と選択範囲の数を追加する | `TextBuffer::len_chars()`、範囲の切り出し |
| 表示倍率 | 現在値と、倍率を選ぶメニューを追加する | `zoom`、`set_zoom()`、`reset_zoom()` |
| AIへの入口 | 「AIに指示」を残し、利用できない入力状態では無効化する | `open_ai_selection()` と既存の入力先判定 |
| テーマ・自動保存 | 一般設定へ移す | `Settings`、既存の設定ファイル、変更処理 |
| 最近のファイル | ヘッダ左の「ファイル」メニューへ移す | 既存の最大10件の履歴、`open_path()` |
| 開発用の数値 | 通常フッタから外す | 性能測定の機能・記録処理は維持する |

新しい診断画面、読了時間、行・列表示、文字コード切替、AIのモデル切替・費用表示、通知履歴の永続化は今回追加しない。保存処理、下書き保存、外部ファイルの監視、文字列の保存形式、入力先の仕組みを作り直さない。

## 3. 画面と操作

### 3.1 通常のフッタ

フッタは本文の下に置く。サイドバー下部の設定ボタンは現在の位置を保つ。

| 左側 | 余白がある場合の中央 | 右側 |
| --- | --- | --- |
| 保存状態、警告・通知への入口 | 保存以外の直近の操作メッセージ | 全体文字数、選択文字数、倍率、AIに指示、必要な場合の設定 |

表示例は「保存済み」「2,430文字・選択120文字」「100%」「AIに指示」とする。選択がない場合は選択文字数を出さない。件数は3桁ごとにカンマを入れる。本文の拡大率を変えても、フッタ自身の高さや文字の大きさは変えない。

高さはライト・ダークともに `theme.footer_height = 32.0` とする。既存の本文高さ計算とAIポップアップの下端計算が同じ値を参照するようにし、別の固定値を足さない。上段・下段、フッタ用の横スクロール、その専用状態 `footer_scroll` は不要になる。[S1][S2][S7]

フッタ内の文字は既存の小さいボタンと同程度に保ち、幅不足を文字の極端な縮小で解決しない。保存失敗は色だけに頼らず、文言と警告アイコンで示す。

### 3.2 狭い幅

以下の幅は、ウインドウ全体ではなくサイドバーを除いたエディタ列の幅で判定する。既存の `main_column_left` と本文の幅計算を使う。[S1]

| エディタ列の幅 | 常時表示するもの | 「その他」へ移すもの |
| --- | --- | --- |
| 640px以上 | 保存状態、警告・通知、全体と選択の文字数、倍率、AI、必要な設定 | 原則なし |
| 440〜639px | 保存状態、警告・通知、文字数欄1つ、AI、その他 | 倍率と必要な設定。選択中は文字数欄を「選択120文字」にし、全体数をその他へ置く |
| 280〜439px | 保存状態、警告・通知、AI、その他 | 全体・選択の文字数、倍率、必要な設定 |
| 280px未満 | 保存状態と警告の有無を添えた、単一の「状態と操作」入口 | 保存状態の詳細、警告・通知、全体・選択の文字数、倍率、AI、必要な設定 |

640/440/280pxは切替の初期値として実装する。実際のボタン幅が収まることを測定し、あふれる場合は上位の項目を切り取らず、一段狭い構成へ切り替える。長いメッセージや大きい文字数は、詳細に完全な値を残したうえで短縮する。警告を隠したり2行へ折り返したりしない。

通常レイアウトの保証対象はエディタ列280px以上とする。既存の `MAIN_MIN_WIDTH = 280` はサイドバー操作時の制約であり、ウインドウの最小幅ではない。ウインドウ縮小で280pxを下回る場合は上表の単一入口へ集約し、複数ボタンの常時表示を要求しない。今回のために新しいウインドウ最小幅は設けない。

「その他」と「状態と操作」は同じ文字数表示と倍率・AI操作を再利用する。別の設定値や状態は持たない。メニューの内容は開いた時点の現在値から作る。

### 3.3 警告と通常メッセージ

保存状態と、保存以外の直近の操作結果を混同しない。フッタの左端は常に第4節の保存状態を示す。

復旧に関する `draft_recovery_warning` と、現在有効な文書別の保存失敗を、警告入口から確認できるようにする。別タブの保存失敗にも入口を残し、詳細では文書名を添える。現在の文書の保存表示を、別タブの結果で書き換えない。

詳細は既存のクリックで開くメニュー部品を使い、内容を折り返して表示する。画面内に収まる最大幅・最大高さを設定し、`scrollable(true)` と高さ制限を併用して縦スクロールで全文を確認できるようにする。長い原因やパスを省略したままにしない。メニューを閉じても未解決の警告自体は消さない。自動的な再試行、強制上書き、警告を解決済みにするボタンは追加しない。[S12]

保存以外の既存 `self.status` は「直近の操作結果」として利用する。幅に余裕があれば短い文を出し、ない場合は通知入口から全文を読めるようにする。警告と通常メッセージが同時にあれば、同じ詳細内で両方を確認できる。既存の文字列を解析して警告の種類や保存状態を決めない。通常メッセージの既存の解除タイミングを保ち、新しい通知履歴・タイマー・配信機構は設けない。

### 3.4 設定への入口とキーボード

作業フォルダを使っている場合は既存サイドバーの設定入口を残す。単独ファイルの場合はフッタの小さい設定ボタンを残し、狭い構成では「その他」に置く。設定を開く操作は既存の `open_settings()` を呼ぶ。

メニューには `DropdownMenu` と `PopupMenuItem` を使う。設定・ファイル・倍率・詳細の操作のために新しい本文入力経路を作らない。矢印、Enter、Escapeはメニューで処理し、本文へ漏らさない。キャンセル時と倍率確定時は、元の本文選択を保ったまま、開く前の入力先へ戻す。本文から開いた場合は本文へ戻る。物理的な焦点だけ本文へ移し、検索や名前変更の入力先フラグを残す処理は追加しない。設定やファイルを開いた場合は、その既存の操作が決める入力先に従う。

本文で日本語変換中は、倍率・その他・状態と操作・警告詳細のトリガーを、メニューへ焦点が移る前から無効にする。実行ハンドラで遅れて拒否するだけにしない。変換の確定・取消後は通常どおり利用できる。AIは第6.2節の同じ変換中判定を使う。設定やファイルを開く操作は既存の画面遷移の規則に従い、新しい変換の確定・取消処理を足さない。

## 4. 保存状態の正確さ

### 4.1 表示を決める順序

現在の文書は `sessions.active()` から取る。保存できたかどうかは自動保存設定のON/OFFから推測しない。[S3]

| 優先順 | 現在の文書の条件 | 表示 |
| --- | --- | --- |
| 1 | `save_in_flight()` がtrue | 保存処理中… |
| 2 | 有効な保存失敗がある | 保存できませんでした |
| 3 | 保存時に外部変更を検出した記録がある | 外部で変更されています |
| 4 | 保存先ダイアログが失敗した記録がある | 保存先を選べませんでした |
| 5 | `presence() == FilePresence::Missing` | ファイルが見つかりません |
| 6 | 保存先がなく、`work_folder_drafts` に登録されている | 下書き |
| 7 | 保存先がない | 未保存 |
| 8 | 保存先があり、`is_dirty()` がtrue | 未保存 |
| 9 | 上記に該当せず、保存先がある | 保存済み |

優先順2〜4は後述する1件の保存問題の種類による。再保存中は「保存処理中…」を表示するが、前回の失敗を警告入口から消さない。短縮時は「処理中」「保存失敗」「外部変更」「保存先エラー」などを用い、詳細では完全な文言を表示する。

`save_in_flight()` はファイル名変更のための保存枠予約にも使われる。そのため「保存処理中…」には書き込みとファイル名変更を含む。別の進行状態は追加しない。

空の無題文書は `dirty == false` でも「保存済み」にしない。「下書き」は通常ファイルとして未保存であることを詳細で説明し、復旧用ファイルへの書き込み成功を保証する表現にしない。現行の下書き保存は書き込み結果を表示用に保持していないため、今回は「下書き保存済み」を追加しない。[S4]

外部変更は、既存の保存時の競合検出を表示する。フッタのために常時監視を新設しない。「保存済み」はHaneが把握する保存済み版と現在の文書が一致することを示し、外部アプリの現在状態を常時確認したという意味にはしない。

### 4.2 追加する状態

通常の保存状態は既存の文書管理から導き、重複する保存状態機械を作らない。追加するのは文書別の保存問題の記録だけとする。

```rust
enum DocumentSaveProblem {
    Failed(String),
    Conflict,
    SaveAsDialogFailed(String),
}

struct ScopedSaveProblem {
    instance: DocumentInstance,
    target_path: Option<PathBuf>,
    problem: DocumentSaveProblem,
}

// EditorViewの表示用状態。ディスクには保存しない。
save_problems: HashMap<SessionId, ScopedSaveProblem>
```

タブを識別する `SessionId` と、同じタブの文書差し替えを識別する既存の `DocumentInstance` を使う。後者には文書の世代と作業フォルダの世代があり、IDを再利用した別文書への誤適用を防げる。[S1]

`target_path` は失敗した保存要求の保存先とする。「名前を付けて保存」が失敗したときに、元のファイルと失敗先を取り違えないために保持する。ダイアログ自体の失敗では保存先未決定としてNoneにする。

### 4.3 更新と解除

既存の文書識別と保存要求の照合を通過した後でだけ、表示用の記録を更新する。新しい照合規則や保存チケットは作らない。[S3][S4]

| 既存の結果 | 表示用の記録 |
| --- | --- |
| `SaveOutcome::Saved` | その文書の問題を解除する |
| `SaveOutcome::SavedStale` | その文書の問題を解除する。現在の文書には追加編集が残るため、通常表示は未保存になる |
| `SaveOutcome::Conflict` | その文書と保存先に競合を記録する |
| `SaveOutcome::Failed` | その文書と保存先に原因を記録する |
| `SaveOutcome::Superseded` | 問題の記録を更新も解除もしない |
| 保存先ダイアログの失敗 | 要求時の文書がまだ同じ場合だけ記録する |
| 保存先ダイアログのキャンセル | 問題を追加しない。既存の未解決問題も解除しない |

再試行開始、追加編集、タブ切替、別タブの保存成功では解除しない。今回の記録は「最新の保存操作で発生した問題」であり、その文書の有効な保存成功で解除する。Save As先への保存完了を別に保証する履歴管理にはしない。

例えば `A.md` を `B.md` へ「名前を付けて保存」して失敗した場合、警告には失敗先 `B.md` を残す。その後、現在の保存先 `A.md` への通常保存または自動保存が成功したら警告を解除し、`A.md` の現在状態を表示する。これは `B.md` の保存成功を示さない。

記録を読むときも `DocumentInstance` の一致を確認する。文書が差し替わった古い記録は表示せず、そのIDの記録を破棄できる。タブを閉じたら該当IDを削除し、作業フォルダを切り替えたら全件削除する。`on_document_replaced()` は通常のタブ切替でも呼ばれるので、そこで全件削除してはいけない。

### 4.4 接続する既存経路

`save_session()` の保存開始・待機、`finish_save()` の成功・失敗は、共通の `self.status` を現在文書の保存表示として使わないようにする。保存由来の `Saved`、`Saving`、`Save queued`、`Saved snapshot`、`Save failed`、競合メッセージの代入を整理し、第4節へ接続する。

保存先未指定を案内する `SaveDecision::NeedsPath` は、通常の案内として残してよい。別文書を対象とする場合は対象名を明示する。

`handle_save_as_response()` と `handle_save_as_for_close_response()` のダイアログ失敗も同じ文書別記録へ入れる。「保存して閉じる」の解除・継続条件、保存成功後の履歴更新、H1による名前の調整、追加保存の実行順は変えない。

## 5. 文字数

### 5.1 数え方

保存する元のテキストに含まれる文字を数える。見た目では一つの文字でも、複数の文字情報で構成される場合は複数として数える。この単位はUnicodeスカラー値で、Rustの `char` と既存 `TextBuffer::len_chars()` に一致する。

| 入力 | 数 |
| --- | ---: |
| `Aあ😀` | 3 |
| 半角スペース、タブ、Markdown記号 | それぞれ含める |
| LF、CR、CRLF | それぞれ1、1、2 |
| `e` と結合アクセント | 2 |
| `👨‍👩‍👧‍👦` | 7 |

表示された本文だけを数えたり、Markdown記号を除いたり、Unicode正規化を行ったりしない。全体と選択で同じ定義を使う。補足表示は「元のテキストの文字数です。空白・改行・Markdown記号を含みます。結合文字や連結した絵文字は複数文字になる場合があります」とする。

### 5.2 実装方法

全体は `editor.document().len_chars().0` を使う。選択範囲は既存の `Selection::range()` を使い、正方向・逆方向を同じ範囲として扱う。[S5]

`BufferSlice` に次の読み取り用メソッドを追加する。

```rust
impl BufferSlice<'_> {
    pub fn len_chars(&self) -> CharLen {
        match self {
            Self::Rope(slice) => CharLen(slice.len_chars()),
        }
    }
}
```

選択数は `document.slice(selection.range())` の結果から取得する。範囲検証は既存APIに任せ、不正範囲を勝手に補正したり0文字と偽ったりしない。通常経路では有効範囲であることをテストし、異常時は選択数を表示しない。

文字数のために `full_text()`、`selected_text()`、`to_string()`、全文の `chars().count()` を呼ばない。Ropeが保持する長さを利用し、全文コピー・全文走査・独自キャッシュ・非同期集計を追加しない。Rope/RopeSliceの長さ取得は定数時間、選択範囲への位置変換は文書長に対して対数時間で行える。[S5][S10]

入力、削除、貼付け、AI置換、Undo/Redo、タブ切替では、通常の再描画で現在の文書と選択を読み直す。追加の更新通知経路を作らない。

日本語の変換中も、全体文字数には現在の文書に反映されている変換中文字を含める。取消で元の値に戻る。変換中の内部選択を通常の文章選択と誤解させないため、`editor.ime().is_some()` の間は選択文字数を表示しない。確定・取消は既存の処理に任せる。

## 6. 倍率とAI

### 6.1 倍率

現在値は `self.zoom * 100.0` を四捨五入した整数の百分率で表示する。`raw_zoom` はホイール操作の到達予定値なので表示に使わない。[S6]

倍率ボタンは、75%、100%、125%、150%、200%の選択メニューを開く。選択した値が実際の倍率に一致するときだけ選択印を付ける。四捨五入した表示が100%という理由だけで100%を選択済みにしない。

100%は既存の `reset_zoom(cx)`、その他は `set_zoom(value, viewport_height / 2.0, cx)` に接続する。メニューで確定したときは残っている `scroll_inertia` を止める。ホイールアニメーションの停止、上下限、100%付近への吸着、本文位置の保持は既存の倍率変更経路に任せる。

メニューでホイールの補間を中断した場合、確定後の倍率が直前の描画倍率と同じでも、既存 `apply_direct_zoom_factor()` と同様に `rebuild_height_estimates()` と再描画で本文の高さを確定する。`set_zoom()` の同値時の早期returnだけで終わらせない。必要ならフッタ用の薄い接続処理で中断の有無を保持する。倍率が変わる通常経路では既存の再配置処理を使い、新しい倍率計算を作らない。[S6]

ホイール・ピンチは現在どおり50〜300%の連続した倍率を使い、メニューに並んだ値へ限定しない。既存のCtrl/Cmd+0も維持する。倍率をタブ別にしたり、次回起動へ保存したりしない。

倍率操作で本文・選択・編集履歴・dirty状態を変えない。`after_input()` は呼ばない。拡大に伴う配置変更では、既存の中央位置を基準にしたスクロール調整を許容し、`scroll_y` の数値そのものが不変であるとは要求しない。

### 6.2 AIへの入口

既存の `open_ai_selection(window, cx)` を呼び、本文選択を読み取る。フッタ側で選択範囲やAI要求を作り直さない。モデル名、接続情報、停止、結果確認は既存AI画面に残す。[S7]

別の入力欄を操作中や日本語変換中など、既存入口が無条件で戻る状態ではボタンも無効にする。入口と表示側が同じ小さな判定を共有し、同じ条件を二重に列挙しない。対象は少なくともAI画面表示中、設定中、名前変更中、サイドバーの絞り込み欄、文書内検索欄、本文の変換中である。これは既存Issue #516と重なるので、同時に別実装を作らず、本改修の受入証拠を共有する。

本文に選択がない場合や空白だけを選択した場合は、既存の選択を促す案内を保つ。ボタンの有効判定のために毎描画時に選択全文をコピーしない。空白判定は既存入口で実行時だけ行う。AIボタンを押したことで本文の選択が消えないことを確認する。

## 7. 一般設定と最近のファイル

### 7.1 一般設定

一般設定の上部に「表示」「保存」を追加する。設定値は即時反映・即時保存し、新たな保存ボタンは設けない。

| 項目 | 表示 | 処理 |
| --- | --- | --- |
| テーマ | システムに合わせる／ライト／ダーク | 選んだ `ThemePreference` を直接渡す |
| 自動保存 | 「変更を自動保存する」チェックボックス | 選んだbool値を直接渡す |

`cycle_theme()` の現在の処理を `set_theme(preference, window, cx)` へ集め、テーマ色の反映、`sync_component_theme()`、必要な描画情報の更新を維持する。現在の値を選び直しただけなら不要な再構築はしない。

`toggle_autosave()` は `set_autosave(enabled, cx)` を呼ぶ薄い処理にし、チェックボックスと既存の切替キーが同じ処理を通るようにする。有効化時は既存の `schedule_autosave()` に接続する。無効化は以後の自動保存要求を止めるが、開始済みの書き込みを取り消さない。既存の文書識別・タイマー照合は保つ。

既存の `Settings.theme`、`Settings.autosave` と設定ファイルを使い、既定値・保存形式・場所を変えない。[S8]

設定の書き込み失敗は、一般設定内に「設定を保存できませんでした」と原因を表示する。現在の画面への反映とディスクへの保存成功を区別し、「この起動中は反映されていますが、次回起動時に戻る可能性があります」と説明する。既存 `store_settings()` の結果を使い、一般設定用の保存エラー1件を保持する。成功した設定書き込みで解除する。Windows連携専用の `settings_error` とは混ぜない。既存の本文側への通知も失わない。

### 7.2 ファイルメニュー

現行コードにはこの用途のネイティブなファイルメニューがないため、ヘッダのタブ列の左に、macOS/Windows共通の小さい「ファイル」ボタンを置く。[S1][S9]

メニューの内容は「ファイルを開く…」「フォルダを開く…」と「最近開いたファイル」の一覧に限定する。既存の開く処理を呼び、新しいファイル管理機能を増やさない。

最近のファイルは既存 `recent.entries()` の順序と上限10件を使う。表示中のファイルを除く現在のルールを維持する。履歴が空なら「最近開いたファイルはありません」と表示する。同名ファイルは親フォルダも表示して区別し、必要な場合は完全なパスを詳細で確認できるようにする。[S8]

選択時は既存 `open_path(&path, cx)` を呼ぶ。別タブですでに開いている場合の再利用、未保存内容の保護、存在しないファイルのエラーは既存の処理に任せる。メニューを開くたびに全履歴へファイルI/Oを行わない。履歴の削除・検索・ピン留めは追加しない。

タブ列にある `on_editor_mouse_down` を、ファイルボタンを含むヘッダ全体へ広げない。ファイルボタンで別の入力欄の焦点や本文選択を先に変更しないよう、タブ領域と操作領域を分ける。

## 8. 実装箇所と順序

新しい表示の組立はprivateな `view/footer.rs` に置く。既存 `EditorView` から呼び、アプリ全体の状態管理や汎用的な通知管理を新設しない。型名は本書を基本とし、同じ責務の既存型が実装時点であればそれを使う。

| ファイル | 主な変更 |
| --- | --- |
| `crates/ui/src/view/footer.rs`（追加） | 保存表示の導出、文字数、倍率・警告・その他メニュー、幅ごとの配置、局所テスト |
| `crates/ui/src/view.rs` | 新部品の配線、保存問題mapと設定保存エラー、閉じる/フォルダ切替時の整理、一般設定、上部ファイルボタン、旧フッタと開発数値の組立削除 |
| `crates/ui/src/view/session_save.rs` | 既存照合後の保存問題の記録・解除、通常Save As失敗の接続 |
| `crates/document/src/lib.rs` | `BufferSlice::len_chars()` と範囲の回帰テスト |
| `crates/ui/src/view/viewport.rs` | 必要なら倍率メニュー用の薄い接続。既存の倍率計算は維持 |
| `crates/ui/src/view/ai_selection.rs` | 既存入口の利用可否判定の共用。AI処理自体は維持 |
| `crates/ui/src/theme.rs` | 両テーマのフッタ高を32pxへ揃える |
| `scripts/hosted_file_tabs_gui.py` | テーマ変更を旧フッタクリックから一般設定の選択へ変更 |
| `README.md`、関連する既存テスト | 操作案内と実画面確認手順を新しい導線へ合わせる |

実装は原則として一つの機能PRで行う。広範なリファクタリングや別の新機能を混ぜない。作業順は、設定・履歴の移設先を用意する、保存問題と文字数の読取を接続する、1行フッタへ切り替える、既存テストと画面確認手順を更新する、の順とする。移設先がない状態で既存入口だけを削除しない。

テーマ確認の既存スクリプトは `Theme (System|Light|Dark)` をフッタから探してクリックしている。設定へ移した後は「設定を開く→テーマを選ぶ→本文へ戻る」へ変更し、選択タブの背景とパスコピーの既存検証内容を維持する。検証用の仕組みを新設したり、古い手順が失敗するのを無視したりしない。[S9]

調査時点の実装経路では `scripts/hosted_file_tabs_gui.py` は保護パスに該当しないため、同じ機能PRで画面変更に合わせて更新する。`.github/` や作業権限の変更は本改修に含めない。実装開始時はcurrentなHane作業手順の変更可能範囲を再確認する。[S11]

自動テストは、文書の長さ、保存状態の導出と遅い結果の拒否、操作による選択保持に絞って追加する。画面の文字列や実装の定数をそのまま写すだけのテストを増やさない。保存本体の既存テストは維持する。

実装PRではcurrentなリポジトリの必須確認を使う。基準は `cargo test --workspace --all-features` と `cargo clippy --workspace --all-targets --all-features -- -D warnings`。通常構成とreleaseへの影響も既存のCI・作業手順に従って確認する。文書だけの設計PRに製品の全テストを要求しない。

画面確認はmacOSとWindowsで、上の変更に絞ったシナリオを行う。Windowsは既存の接続先papa-winで直接確認し、キー確認時はKeyhacのフックを停止、終了後に戻す。検証用に起動した余計なプロセスは終了する。現時点ではこれらを実施済みとはしない。

Hosted GUIは既定ブランチ由来の手順を実行するため、機能PR内のテーマ操作更新はmerge前のHosted runへ反映されない。今回のGUI受入には、既存手順に従うmacOS/Windowsの直接GUI確認を用いる。対象のcurrent PR headとシナリオに影響するbase contextを確認し、「一般設定でテーマ選択→本文へ戻る→選択タブの背景・パスコピー」と本書の変更箇所を検証して、観測結果と画面を実装PRに残す。旧Hosted手順の結果は観測できた範囲で記録し、新しい導線の合格根拠として扱わない。workflowや権限制御は変更しない。[S13]
