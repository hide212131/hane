# Issue #608 実装準備

- 基準 SHA: `68c438aea3ce39e12b25aa4ad3e2f5e16294190d`（main）
- 状態: 実装・回帰テスト・GUI検証は未実施

## 採用する既存経路

Issue #39 で受け入れ済みの Work Folder 新規メモ経路と H1 によるファイル命名を使う。`crates/ui/src/view/sidebar.rs` の `SidebarContextTarget::Folder(path)` が保持する対象パスを、`crates/ui/src/view.rs` の新規メモ作成処理へ明示的に渡す。ツールバーからの既存操作は引き続き `selected_folder` を作成先にする。

フォルダ行のメニュー組立は `sidebar_context_menu_element`、新規メモの作成先選択と draft 登録は `new_work_folder_note` 周辺にある。既存の draft recovery、H1 自動命名、保存・サイドバー反映の責務を複製しない。右クリック時の対象フォルダが現在の Work Folder に存在することと、フォルダをゴミ箱へ移動中の拒否動作を維持する。

## 今回の範囲

- 子フォルダの右クリックメニューに新規メモ開始の項目を追加する。
- その項目から始めた新規メモの保存先を右クリック対象フォルダにする。別フォルダが選択中でも対象を取り違えない。
- ツールバーからの作成は従来どおり選択フォルダを使う。
- 対象フォルダ、別フォルダが選択中のケース、既存ツールバー経路を確認する GPUI 回帰テストを追加する。
- macOS / Windows の focused GUI scenario で右クリック、メニュー表示、作成開始、対象フォルダへの反映を確認する。

## 対象外

- Work Folder ルート行、ファイル行へのメニュー追加。
- ファイル名入力 UI や H1 自動命名の変更。
- 新規フォルダ作成、削除、移動、サイドバー全体の再構成。

## 実装上の条件

- Issue #39 の選択フォルダ作成と同じ新規メモ・draft・保存経路を使う。
- コンテキストメニューの対象パスを暗黙の選択状態へ置き換えない。右クリックしたフォルダを明示的な保存先として渡す。
- 古くなった対象パスを Work Folder ルートへ黙って振り替えない。
- 変更コードと直接関係する回帰テストを追加し、実施できない検証は未実施として報告する。
- この準備文書以外のファイルはこの準備 commit に含めない。
