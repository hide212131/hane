# 設計: 背景の質感（紙・壁）とインクの「染み・乾き」

対象: hane v0.54.1（main `f93b979b`）／前提機能: 乾くインク（Issue #779, #782）
種別: 設計のみ（この文書では実装しない）

## 1. 目的

乾くインクは、確定直後の文字をわずかに濃く描き、時間とともに通常色へ戻す機能である。ダークテーマでは明度シフトを2倍（ΔL 0.08）にしても「あまり目立たない」という評価だった。

実物のインクの乾きは、文字色そのものより紙との関係で知覚される。濡れた紙は暗く沈み、繊維の凹凸が見えにくくなる（艶が出て平らに見える）。乾くと紙の地合いが戻り、インクは紙と一体化する。無地の背景にはこの「地合いが消えて戻る」という手がかりが存在しない。そのため明度差だけに頼ることになり、ダークでは特に弱い。

本設計では次の二つを組にして導入し、乾きを紙との関係で見せる。

- **質感（texture）**: 編集面に、紙または壁の静的な地合いを敷く。
- **染み（soak）**: 濡れている範囲の背後で地合いを平らにし、わずかに沈ませる。乾きの4段階に合わせて薄れる。

中心となる考え方は次のとおり。**染みは「暗くする」だけではなく「質感を覆って平らにする」**。半透明の平坦色を質感の上に重ねると、質感のコントラストは (1−α) 倍に下がる。この「地合いの消失と回復」は、ライトでもダークでも明度の向きに関係なく働く。ダークで弱かった明度差を補う、もう一つの手がかりになる。

## 2. 現行実装の要約（読んだ範囲）

### 2.1 台帳とパラメータ（`crates/ui/src/ink.rs`）

- `InkLedger` は、確定した範囲とその時刻を `SourceRange` で持つ。文書は `RopeBuffer::deltas_since` で追従するだけで、書き込まない。
- `WET_LEVELS = 4`。`level = clamp(ceil(4·(1 − age/D)), 0, 4)` で、age は `DRY_TICK = 5s` のグリッドで量子化した値を使う。既定 D = 60s なので、15s ごとに 4→3→2→1→0 と下がる。
- `InkFrame { wet: Vec<(SourceRange, u8)>, band: Option<(SourceRange, f32)>, params }` を、1フレームに1回 `frame()` で作る。
- 帯（band）は、句点（`。！？`）または本文中の Enter で、直前の確定の連なりに出る。`BAND_HOLD` 600ms は不透明度 1.0、その後 100ms ごとに 0.75 / 0.5 / 0.25 となり、900ms で消える。最大 4096 バイト。
- 色は OKLab の明度だけを動かす。`ink_color` はライトで −ΔL·level/4、ダークで +2·ΔL·level/4（`DARK_DELTA_L_FACTOR = 2.0`）。`band_color` は背景を「文字側」へ ΔL 動かす（ライトは暗く、ダークは明るく）。
- 強さは `DryingInkStrength` で決まる。`delta_l` が弱 0.025 / 標準 0.04 / 強 0.06、`band_delta_l` が 0.02 / 0.03 / 0.045。

### 2.2 タイマー（`crates/ui/src/view/drying_ink.rs`）

- タイマーは常に1本以下。`next_wakeup` が返す次の変化時刻まで眠り、起きたら `cx.notify()` するだけである。アニメーションフレームは要求しない。
- **補足**: 水準の変化は5秒グリッドに揃っている。ただし帯の段階（600/700/800/900ms）も同じタイマーで起こしているので、現状でもグリッド外の起床がある。本設計は**新しい起床を一切足さない**（§5）。
- Reduce Motion は帯の発火時だけ読み、帯だけを抑止する（乾きは色変化であって動きではない、という扱い）。
- 読書モード（`!body_editable()`）では時間は進むが、何も描かない。IME 変換中は帯を隠す。

### 2.3 描画（`crates/ui/src/line.rs` `row_element`）

- 1行（row）は flex の `div` で、テキストはセグメントごとの子 `div` になる。セグメントは、カーソル・選択・IME・検索・リンク・インク境界で分割される（`line_segments_with_ink`）。
- セグメントの背景は排他的な優先順で塗られる: 選択 → 検索の現在一致 → 検索一致 → 帯（最も低い。`segment_shows_band` が選択・検索と排他にしている）。帯がかかる区間では `text_bg`（インラインコード背景）を抑止する。
- 文字色は、構文色 → リンク色 → 最後に `segment_ink_color` の順。検索一致と IME 変換中の文字は色を変えない。
- ブロック面（コード・表・メディア・メタデータ）は `styled_block` が行 `div` に不透明な `bg` として塗る。

### 2.4 背景（`crates/ui/src/view/render.rs`）

- ウィンドウのルート `div` に `.bg(editor_background)`（ライト `#faf9f7`、ダーク `#1f2022`）。編集面には専用の背景描画がない。
- 本文は `#editor-body`（`relative`、`overflow_hidden`）の中に、`top(content_top_for_scroll(scroll_y))` で絶対配置された列として描かれる。
- サイドバー、検索結果パネル、設定画面は `sidebar_background` を自分で塗っている。

### 2.5 GPUI で使える経路（リポジトリ内で使用実績を確認したもの）

| 経路 | 実績 |
| --- | --- |

| `Arc<RenderImage>` の生成・表示・破棄 | Mermaid（`img(...)` で表示、`cx.drop_image(image, Some(window))` で atlas から外す） |

- `Window::paint_image(bounds, corner_radii, Arc<RenderImage>, frame_index, grayscale)` と `Window::paint_shadows(bounds, corner_radii, &[BoxShadow])`（`blur_radius` つき）は、同梱の履歴版 GPUI 0.2.2 で確認した。現行の gpui-pre 0.3.6 のソースは今回の作業環境から読めなかった。そのため**この二つは P1/P2 の最初の作業で 0.3.6 上のシグネチャを確認する**（§7 の spike 項目）。確認できない場合の代替も各所に書く。

## 3. 設計

### 3.1 背景の質感

#### 3.1.1 生成方法: 手続き生成のタイル（アセットは埋め込まない）

- **手続き生成を採る理由**: (a) テーマ色（`editor_background`）と強さから毎回導出できるので、テーマを変えても色がずれない。(b) 表示倍率（1x/2x/1.5x）ごとに等倍の画素で作れるので、拡大縮小によるぼけが出ない。(c) バイナリにアセットとライセンスの管理が増えない。(d) シード固定で決定的になり、テストでハッシュを比較できる。
- **タイルの大きさ**: 論理 384×384px。装置画素では `round(384 × scale_factor)` 角で、2x なら 768² × 4B ≈ 2.4MB。384px は標準行高 26px の約15行分である。これより小さいと特徴の繰り返しが目に付きやすい。大きくするとメモリと生成時間が二乗で増える。
- **生成内容**: ΔL 場（OKLab の明度差）を作り、`editor_background` に適用した**不透明な**画像にする。
  1. 低周波のむら（mottling）: 周期的な勾配ノイズ。タイルあたり 3 周期と 6 周期（特徴の大きさ約 128px / 64px）。
  2. 繊維（ライトの紙のみ）: 約 150〜200 本の短い曲線。長さ 20〜80px、幅 1〜1.5 装置画素、アンチエイリアスつき。背景より暗い向き。
  3. 細粒（tooth）: 1〜2px 周期のノイズ。振幅はごく小さくする（§3.1.3）。
- **色の適用**: ΔL を 1/1024 単位で量子化し、`shift_lightness(editor_background, ΔL)` の結果を参照表にしてから画素を埋める。値の種類は数十なので、画素ごとの OKLab 変換は不要になる。`shift_lightness` などの OKLab 関数は、現在の `ink.rs` から共通の色モジュールへ移して共有する。
- **生成の場所**: Mermaid と同じくバックグラウンドで生成し、完成したら差し替える。生成が終わるまでは質感なし（現行の無地）で描く。テーマ切替時の一瞬の無地は許容する。
- **キャッシュキー**: `(テーマ種別 light/dark, 質感の種類, 強さ, scale_factor を 1/100 で丸めた値)`。キーが変わったときだけ再生成し、古い画像は `cx.drop_image` で atlas から外す。

#### 3.1.2 継ぎ目対策

- **周期境界での生成**: ノイズの格子は添字を周期で剰余し、繊維はタイル端をまたぐものを反対側にも描く（トーラス状）。これで上下左右に並べても数学的に連続になる。
- **画素位置の整数化**: `paint_image` は bounds の原点を切り捨て、大きさを切り上げる（0.2.2 で確認）。端数の位置では 1 装置画素の重なりや隙間が出る。そこで次のようにする。
  - タイルの論理寸法 × scale_factor を整数にする（384 は 1x / 1.5x / 2x で整数）。
  - スクロール量から作るタイル原点を装置画素単位に丸める（`round(y × scale) / scale`）。
  - これで各タイルは texel 中心にちょうど対応し、atlas 上の隣接タイルからの滲み（線形補間によるもの）も起きない。
- **繰り返しの目立ち**: P1 は単一タイルとし、目立つ特徴を置かない（振幅予算で抑える）。P3 では、周期の異なる二層（例: 384px のむら層と 293px の繊維層、互いに素）を重ね、合成周期を事実上なくす案を検討する。

#### 3.1.3 コントラスト予算（数値）

基準: 現行テストの `syntax_colors_keep_contrast` と同じく、**本文と構文色のすべての前景トークンが、質感・染みを合成した後の最悪の背景に対して WCAG コントラスト 4.5 以上**を保つ。

| テーマ | 背景 OKLab L | 最も厳しい前景（無地背景でのコントラスト） |
| --- | --- | --- |
| ライト | `#faf9f7` → 約 0.982（Y≈0.947） | リンク `#2867a9`（Y≈0.131、5.5）、引用 `#6b6259`（Y≈0.126、5.7） |
| ダーク | `#1f2022` → 約 0.243（Y≈0.0144） | 引用 `#aaa39a`（Y≈0.371、6.5） |

- **ライトの背景明度の下限: L ≥ 0.920**（Y ≥ 0.779）。このときリンクは (0.829)/(0.181) ≈ 4.59、引用は ≈ 4.71 で、どちらも 4.5 以上。L 0.910 ではリンクが約 4.48 になり 4.5 を割るので、下限を 0.92 とした。
- **ダークの背景明度の上限: L ≤ 0.255**。引用は約 6.3 になる。ダークで背景を暗くする向きは、明るい文字とのコントラストを上げる方向なので、制約にならない。

質感の振幅（無地背景からの ΔL）:

| | ライト（紙） | ダーク（壁） | 根拠 |
| --- | --- | --- | --- |
| 範囲 | −0.020 〜 +0.006 | −0.018 〜 +0.008 | ライトは最暗でも L 0.962 で、下限 0.92 まで 0.042 の余裕が残る。この余裕は染みに割り当てる（§3.2.4） |
| RMS | ≤ 0.006 | ≤ 0.006 | 無地との差が「気配」程度に留まる量 |
| 2px 以下の高周波成分の振幅 | ≤ 0.004 | ≤ 0.003 | 文字の線幅（1〜3px）と同じ空間周波数の雑音が、可読性を最も損なうため |
| 明るい向きの成分 | 小さく | **小さく（+0.008 以下）** | 暗い面の上の明るい点は画面の埃や傷に見える。そのためダークは主に暗い向きのむらで作る |

#### 3.1.4 テーマ別の方向性

- **ライト = 上質紙（画用紙寄りの地合い）**: わずかに暖色の地（`editor_background` そのもの）に、低周波のむらと細く淡い繊維を重ねる。色相は変えず、明度だけを変える（既存の色関数の契約と揃える）。
- **ダーク = 土壁／漆喰**: 低周波のむらを主にし、暗い向きの細かい粒を加える。長い繊維は入れない。明るい繊維は傷に見えやすく、暗い繊維は暗い地の上ではほとんど知覚されないためである。黒和紙（暗い繊維）は P3 で種類の追加として扱う。

#### 3.1.5 適用範囲

| 領域 | 質感 | 理由 |
| --- | --- | --- |
| `#editor-body` 全体（テキスト列と左右の余白を含む） | **あり** | 「紙」は本文の面全体である。テキスト列だけに敷くと、列の端に見えない境界線ができる |
| サイドバー、タブバー、ヘッダー、フッター、検索バー | なし | 道具（chrome）と紙を区別する。現状どおり自前の背景色を塗る |
| コードブロック、表、メディア、Front Matter の面 | なし（不透明な面がそのまま覆う） | 「紙に貼ったカード」として読める。既存の `styled_block` の `bg` が質感の上に塗られるので、追加の変更は不要 |
| インラインコードの `text_bg`、選択、検索ハイライト | なし（不透明なので覆う） | 状態表示は地合いより優先する |
| 設定画面など、本文を置き換える画面 | なし | 本文ではないため |
| 読書モード、プレーンテキストモード | あり | 紙は紙である。染みは現行どおり読書モードでは出さない |

#### 3.1.6 描画経路とキャッシュ

- **要素**: 新しい自前の `Element`（仮称 `PaperTexture`）を作り、`#editor-body` の**最初の子**として `absolute`・全面に置く。`paint` の中で、自分の bounds を覆うタイル枚数だけ `window.paint_image(...)` を呼ぶ。
- **スクロールとの関係**: タイルの縦の原点は `−(scroll_y mod タイル高さ)` を装置画素に丸めた値にし、**紙が文書と一緒に動く**ようにする。固定にすると、文字が地合いの上を滑って「泳ぐ」ように見え、スクロールが落ち着かない。横は `#editor-body` の左端に固定する。
- **ズーム**: 質感は論理 px 固定で、文字のズームに合わせて拡大しない（紙の目は文字の大きさで変わらない）。
- **再生成しないもの**: スクロール、リサイズ、入力、ズーム。これらはタイルの配置（`paint_image` の bounds）だけが変わり、atlas への再アップロードも起きない（atlas は画像 ID をキーにしている。0.2.2 で確認）。
- **描画コスト**: 1600×1000 の編集面で、384px タイルなら 5×4 = 20 枚程度。スクロール中の部分タイルを含めても 30 枚以下である。GPUI は同じテクスチャのスプライトをまとめて描くので、増えるのは実質1バッチになる。
- **`paint_image` が 0.3.6 で同じ形で使えない場合の代替**: `img(Arc<RenderImage>)` の `div` を格子状に絶対配置する。Mermaid と同じ経路で、要素数は 20〜30 個増える。

キャレットと選択は、質感と染みより必ず上に来る。染みが選択を覆うことはない（選択は不透明なので、染みは選択の下に隠れる）。

### 3.2 染み（soak）

#### 3.2.1 表現

濡れている範囲（`InkFrame.wet`）の背後に、水準に応じた不透明度で**平坦な染み色**を重ねる。視覚効果は二つある。

1. 地合いを (1−α) 倍に平らにする（主な手がかり）。
2. 背景を少し沈ませる（副次的な手がかり）。

乾くにつれ α が下がり、地合いが戻る。

#### 3.2.2 染み色（テーマ別）

染み色 = `shift_lightness(editor_background, −s)`。ライトもダークも**暗くする向き**にする。濡れた紙も、濡れた土壁やコンクリートも暗く沈む。これは日常的によく知られた見え方である。

| 強さ | ライト s | ダーク s | 根拠 |
| --- | --- | --- | --- |
| 弱 | 0.033 | 0.030 | ライトは `band_delta_l × 5/3`。帯（短時間・全面不透明）より持続する分、α を下げて相殺する前提の量 |
| 標準 | 0.050 | 0.045 | |
| 強 | 0.075 | 0.065 | ライトは §3.2.4 の下限計算で上限 0.078 以下 |

ダークを暗くする向きにすると、現行の帯（ダークでは明るくする向き）と方向が逆になる。染みが有効なときの帯の扱いは §3.2.6 で決める。ダークで明るくする向き（濡れた面の艶）にする案は U-5 とする。

#### 3.2.3 4段階との連動

`α(level) = 0.18 × level`。level 4〜1 で **0.72 / 0.54 / 0.36 / 0.18**、level 0 は描かない。

- 実効的な沈み ΔL = α·s。ライト標準なら 0.036 / 0.027 / 0.018 / 0.009 で、水準に比例する。`ink_color` も ΔL·level/4 の線形なので、段階の刻み方が文字色と揃う。
- 地合いの残り = 1 − α = 0.28 / 0.46 / 0.64 / 0.82。level 4 では質感の見かけの振幅が3割未満になり、「平らで沈んだ」面として周囲と区別できる。
- level 4 の実効 ΔL 0.036 は、現在「見える」と評価されている帯の ΔL 0.03 を上回る。level 1 の 0.009 は、柔らかい輪郭では知覚の閾値付近になる。「ほぼ乾いた」状態として意図どおりの見え方である。
- 段階は `InkFrame.wet` の水準をそのまま使う。台帳もタイマーも変更しない。

#### 3.2.4 予算の検算（ライト、強、level 4 の最悪ケース）

合成後の L = (1−α)·L_質感最暗 + α·(L_bg − s) = 0.28 × 0.962 + 0.72 × (0.982 − 0.075) ≈ 0.2694 + 0.6530 = **0.922 ≥ 0.920**。

ダークでは暗くする向きなので、コントラストは増える一方である。上限の制約は質感の明るい成分（+0.008）だけになる。

さらに安全側の要素として、濡れた文字自身はライトで暗くなる（`ink_color`）。ただし、この検算はそれに頼らない。染みの輪郭のにじみが乾いた隣の文字にかかる場合も、上の下限で守られる。

#### 3.2.5 輪郭の柔らかさ（GPUI で可能な範囲）

**描く場所**: `row_element` の行 `div` の**最初の子**として、絶対配置の染み片を置く。行内のセグメント（文字）より先に描かれるので、染みは文字の下になる。

- x 範囲: `row_ink_visuals` が返す行内の可視範囲（隠れた記法の上の濡れは、既存と同じ射影で除外される）を x 座標に変換したもの。変換には、公開されている `BlockLayout::point_for_source` を範囲の両端に使う。または、非公開の `LayoutLine::x_for_visual` を presentation 側で公開する。どちらにするかは実装時に選ぶ。座標の基準は、キャレット位置（`caret_geometry` が `line_horizontal_padding` を足している規約）に揃える。
- y 範囲: 行の内側に収める（§下記）。
- 同じ行で隣り合う同じ水準の範囲は、一つの片にまとめる（`InkFrame` は隣接する同水準の範囲を既に結合している）。

**柔らかさの方法（優先順）**:

1. **ぼかし影による柔らかい矩形**: 染み片を `paint_shadows`（または Styled の box shadow）で描く。`offset = 0`、`blur_radius = r`、`spread_radius = −r/2` 程度、角丸つき。r は `0.25 × 行高`（標準で約 6px）。ガウスぼかしの縁なので、滲んだ紙に近い見え方になる。**前提として、影がテキスト背景を持たない要素の内側も塗ることを 0.3.6 で確認する**（spike）。
2. **代替: 段付きの角丸矩形の入れ子**: 同心の角丸 `paint_quad` を 3 枚重ね、外側ほど α を下げる（α の 0.35 / 0.35 / 0.30 に分配し、各段 2px ずつ外へ広げる）。ぼかしほど滑らかではないが、`paint_quad` は実績のある経路である。
3. 最終代替: 現行の帯と同じセグメント `bg`（硬い縁）。可視性の評価には使えるが、P2 の受入では 1 か 2 を求める。

**行をまたぐときの扱い**: 縦方向のぼかしは行の内側に収める（片の y 範囲を上下 r だけ縮めて置く）。理由は二つある。

- 次の行の染みは前の行の文字より後に描かれる。下へはみ出したぼかしが前の行の文字の下端（ディセンダ）を薄く覆ってしまう。
- 実物でも、染みは書いた行に沿って出て、行間には紙が残る。行ごとに柔らかく分かれた染みは、不自然ではない。

**横方向のはみ出し**: 同じ行の染み片は行の最初の子なので、横にはみ出しても文字の下になり、問題ない。行 `div` は FrontMatter 以外では `overflow_hidden` でないため、余白側へのにじみも切られない。

**個数の上限**: 1フレームの染み片は 256 個まで。超えたら、行ごとに水準別の外接範囲へまとめる（`MAX_SPANS = 512` の台帳を全部画面に出すような病的な場合の保護）。

**対象外（P2）**: 表の行（`table_row_element`）、図、画像の行、折り畳まれた区切り線。表の行の濡れは、文字色と帯だけを現行どおり続ける。表への染みは P3 で扱う。

#### 3.2.6 既存の帯との関係: 「帯を染みの初期の濃い部分として統合」

| 案 | 評価 |
| --- | --- |
| 置き換え（帯を廃止） | 句点・改行の「書き終えた」区切りの合図は、乾きとは別の情報として価値がある。消すのは早い |
| 併存（帯は現行のまま、セグメントの `bg`） | 硬い縁の帯が柔らかい染みの上に出て、質感が二種類になる。ダークでは帯が明るい向き、染みが暗い向きで、方向が逆になる |
| **統合（推奨）** | 染みが有効なとき、帯は染みと同じ層・同じ描き方（柔らかい片）・同じ色で、α を上乗せして描く。染みが無効なときは、現行の帯とまったく同じに描く |

統合の詳細:

- **範囲・時間・発火条件**: 現行のまま変えない（`InkLedger` の帯をそのまま使う）。起床も現行の 600/700/800/900ms から増やさない。
- **α**: 染み片の α に `0.25 × band_opacity` を加え、0.9 で頭打ちにする（ライト標準なら、確定直後の 0.6s は実効沈み 0.036 → 0.049）。§3.2.4 の下限はこの上乗せ分も含めて満たすこと（強・level 4・帯 1.0 で α 0.9 は L ≈ 0.096 + 0.816 = 0.912 となり、下限を割る）。そこで、帯の上乗せは**下限に当たらない範囲までに制限**する: `α_max = (L_合成なし − 0.92) / ...`。実装では、`(強さ, テーマ)` ごとに事前計算した α の上限表をテストで固定する。
- **向き**: 染みが有効なときは、ダークでも帯は暗くする向き（染みの色）になる。帯の単独表示（染み無効）は現行どおり明るくする向きのままとする。
- **帯の範囲が乾いた文字にまたがる場合**（帯は確定の連なり全体）: 水準 0 の部分にも、帯の上乗せ α だけの片を描く。
- **Reduce Motion と IME**: 帯の発火抑止と IME 変換中の非表示は、現行の `trigger_params` と `drying_ink_frame` がそのまま効く。

### 3.3 文字色との役割分担

- **P1・P2 では明度シフトを据え置く**（ライト ΔL 0.04、ダーク ×2）。理由:
  - 文字色は「インクが濃い」、染みは「紙が濡れている」という別の手がかりで、足し合わせても矛盾しない。どちらも水準に比例する。
  - ダークで染みが十分見えるかは GUI 測定でしか判断できない。同時に二つを動かすと、どちらが効いたのか分からなくなる。
- **役割の整理（文書化のみ）**:
  - 文字色: 1文字単位の正確な濡れ範囲（染みは柔らかく、範囲の端があいまい）。
  - 染み: 面としての手がかり（ダークで主役）。
  - 帯: 区切りの瞬間の合図。
- **P2 の GUI 測定後に再評価する点（U-6）**: ダークで染みが受入基準を満たしたら、`DARK_DELTA_L_FACTOR` を 2.0 → 1.5 に下げる。染みで背景が暗くなる分、文字の明るさが過剰になり「文字が光る」見え方になるのを避けるためである。これは別 PR とし、P2 に混ぜない。

### 3.4 設定

| キー | 型・値 | 既定（推奨） | 依存 | 画面上の位置 |
| --- | --- | --- | --- | --- |
| `paper_texture` | bool | **P1: false → P2 受入後に true を検討（U-1）** | 乾くインクと独立（見た目の設定） | 表示（テーマの近く） |
| `paper_texture_strength` | `weak` / `standard` / `strong` | `standard` | `paper_texture` が off のとき無効表示 | 同上 |
| `paper_texture_kind` | P3 で追加（`paper` / `washi` など） | — | — | — |
| `drying_ink_soak` | bool | **true** | `drying_ink` が off のとき無効表示（`drying_ink_band` と同じ扱い） | 乾くインクの群（帯の隣） |

- **染みの強さ**: 新しいキーを作らず、既存の `drying_ink_strength`（弱・標準・強 → §3.2.2 の s）に従う。設定の数を増やさないためである。乾く速さは `drying_ink_speed` にそのまま連動する（染みは水準を読むだけなので）。
- **質感の強さの倍率**: §3.1.3 の振幅予算に対して、弱 0.6、標準 1.0、強 1.4 倍。ただし強でも §3.2.4 の下限を割らないよう、染みと組み合わせた最悪ケースをテストで固定する。強で予算を超える場合は、質感側を頭打ちにする。
- **染みと質感の組み合わせ**: 染みは質感なしでも描く（無地の上の柔らかい沈みになる）。ただし主な手がかり（地合いの消失）は質感ありで初めて働く。設定画面の説明文で「質感と組み合わせると見えやすい」と案内する。
- **保存形式**: 既存の `key=value` 行に追記する。値が欠けている・不正なときは既定値にする（`drying_ink_*` と同じ `strip_prefix` 方式）。旧版が未知のキーを無視することは、実装時に `store.rs` の読み込みで確認する。
- **Reduce Motion**:
  - 質感: 静止しているので対象外。
  - 染み: 5秒以上の間隔の段階的な色変化で、乾くインクの文字色と同じ扱いなので対象外。
  - 帯（統合後の上乗せ α を含む）: 現行どおり抑止する。
- **OS の「透明度を下げる」「コントラストを上げる」**: GPUI からは読めず、現行でも読んでいない。対象外とし、P3 で必要なら `reduce_motion.rs` と同じ方式の読み取りを検討する。

## 4. （予約）

## 5. 不変条件

1. **文書・レイアウト・キャレット形状・undo 履歴に触らない**。質感と染みは描画時の追加要素だけで構成する。行の高さ、`BlockLayout`、`HeightIndex`、文書のリビジョン、dirty フラグ、`can_undo` / `can_redo` は変わらない。既存の `doc_state` 系テストと同じ観点の回帰テストを、質感あり・染みありの組み合わせで追加する。
2. **キャレット、選択、IME の下線、検索ハイライトは、質感と染みより上に描く**（§3.1.7）。`cursor_overlay` の形と位置の計算は変えない。
3. **質感オフ＋染みオフのとき、描画は現行と一致する**。具体的には:
   - `PaperTexture` 要素を木に入れない（「透明で描く」のではなく、存在させない）。
   - `row_element` の染み層の子を作らない。
   - 帯は現行のセグメント `bg` 経路を通り、`band_fill` と同じ色になる。
   - テスト: 両方オフのとき、`row_element` が出す要素の構造（子の数、セグメントの背景色）が導入前と同じであることを確認する。`band_fill` と `segment_ink_color` の既存テストは変更なしで通る。
4. **アニメーションフレームのループを持たない**。
   - 質感: タイマーなし。
   - 染み: 段階は `InkFrame.wet` の水準をそのまま使い、**新しい起床を足さない**。水準の変化は既存の5秒グリッド上の起床で描き直される。
   - 帯の上乗せ: 既存の帯の起床（600/700/800/900ms）だけを使う。
   - テスト: 染み有効時も、`next_wakeup` が返す列が既存のテスト（`next_wakeup_walks_the_level_steps_and_ends_when_dry` など）と同じであることを確認する。
5. **性能予算**
   - 静止テクスチャはキャッシュし、スクロール・リサイズ・入力・ズームでは再生成も再アップロードもしない。再生成はキャッシュキーの変化時だけにする。
   - 生成時間: Release ビルドで 2x の 1タイルあたり 30ms 以下（バックグラウンド）。UI スレッドでは生成しない。
   - メモリ: 質感の画像は合計 4MB 以下（2x で 2.4MB×1。P3 の二層でも 4MB 以内）。
   - フレーム時間: 既存の計測（`metrics.record_layout` / `record_paint`）で、スクロール中の1フレームあたりの増加を 0.3ms 以下とする（Debug ではなく、計測に使う profile を明示して測る）。
   - 染み片: 1フレーム 256 個以下（§3.2.5）。
6. **時刻**は常に executor の時計を使う（`cx.background_executor().now()`）。テストは `advance_clock` で駆動する。
7. **読書モードでは染みも帯も描かない**（現行の `drying_ink_frame` の挙動を継承）。

## 6. 段階分けと受入条件

### P1: 質感のみ

**範囲**

- `PaperTexture` 要素、タイル生成（ライト紙・ダーク壁）、キャッシュと破棄。
- `paper_texture` / `paper_texture_strength` の設定と設定画面。
- OKLab 関数の共通化。
- 0.3.6 での spike: `paint_image`、`RenderImage::new` の画素並び、`paint_shadows` の内側の塗り（P2 の判断材料）。

**受入条件**

1. 質感オフのとき、本文の描画が導入前と一致する（§5-3 の構造テスト）。
2. 生成したタイルが周期境界で連続している。テストで、タイルの左端と右端、上端と下端の画素列の ΔL の差が、内部の隣接画素間の差の分布の 99 パーセンタイル以下であることを確認する。
3. コントラスト: すべての前景トークン × (ライト, ダーク) × (弱, 標準, 強) について、タイルの最暗（ダークは最明）画素に対する WCAG コントラストが 4.5 以上（既存の `syntax_colors_keep_contrast` と同じ閾値）。
4. 振幅: 生成したタイルの ΔL の範囲・RMS・高周波成分が、§3.1.3 の表の予算内である（テストで数値を固定）。
5. 決定性: 同じキーなら、生成した画像のハッシュが同じになる。
6. スクロールしても再生成されない（生成回数のカウンタをテストで確認）。テーマ・強さ・倍率の変更ではちょうど1回再生成され、古い画像が破棄される。

**GUI での確認**（agent-desktop。macOS は本機、Windows は既定のリモート経路。Debug ビルドで、対象 SHA と実行バイナリの由来を記録する）

- 空行が多い文書を開き、ライト・ダーク × 強さ3段のスクリーンショットを**可逆形式**で取る。
- 測定: 文字のない 128×128 の領域で、OKLab L の標準偏差を測る。質感オンで 0.003〜0.008、オフで 0.0015 以下（量子化誤差のみ）であること。表示のカラープロファイル（Display P3 など）の影響を避けるため、絶対値ではなく**同じ画像内の比較**で判定する。
- 継ぎ目: 384px 間隔の境界をまたぐ 8px 幅の帯で、L の平均が隣接帯との差 0.002 以下であること。目視でも格子が見えないこと。
- スクロール: 本文を連続スクロールし、地合いが文字と一緒に動くこと（固定で泳がない）を短い連続キャプチャで確認する。フレーム時間の増加が予算内であること。
- 利用者の主観確認: 「紙・壁に見えるか」「文字が読みにくくなっていないか」を短く聞いて記録する。

### P2: 染み（帯の統合を含む）

**範囲**

- `drying_ink_soak` 設定。
- `row_element` の染み層（通常の行。表の行は対象外）。
- 柔らかい輪郭: P1 の spike の結果に応じて、ぼかし影または段付き角丸。
- 帯の統合（染み有効時のみ）と α 上限表。

**受入条件**

1. 染みオフのとき、帯を含めて現行と一致する。染みと質感が両方オフのときは導入前と一致する。
2. 新しい起床がない: 染み有効時も `next_wakeup` の列が既存と同じ（§5-4）。
3. 染み片の α が level 4〜1 で 0.72 / 0.54 / 0.36 / 0.18 であり、水準 0 では片を作らない。
4. 合成後の背景の下限: 全 (テーマ, 強さ, level, 帯の不透明度) について、§3.2.4 と同じ計算でライト L ≥ 0.92、ダーク L ≤ 0.255。全前景トークンに対するコントラストが 4.5 以上（テストで表として固定）。
5. 選択・検索一致・IME 変換中の文字・キャレットが染みの上に見える。選択した濡れ範囲では、選択色が変わらない。
6. 文書・undo・dirty が不変であること（§5-1）。濡れ範囲の文字を削除・挿入したときは、台帳の追従（既存）に従って染みも追従すること。
7. 読書モードでは染みが出ない。IME 変換中は帯の上乗せが出ない。
8. 染み片の個数が上限を超えたら、行ごとにまとめる。

**GUI での確認（「見えるようになった」の判定）**

- 手順: 質感オン・染みオン・標準強度で、日本語の段落を IME で入力して確定し、句点で区切る。直後と、15s・30s・45s・60s 後に、同じ位置を可逆形式で撮る（executor の時計に合わせ、各段階が切り替わった直後に撮る）。
- 測定する量（同じ画像内で、濡れ範囲の背後と、同じ行の乾いた範囲の背後を比べる）。文字の画素は、前景色との距離で除外する。

| 量 | ライト level 4 の基準 | ダーク level 4 の基準 |
| --- | --- | --- |
| 平均明度差 \|ΔL\| | ≥ 0.030 | ≥ 0.025 |
| 地合いの比（濡れ側の L 標準偏差 ÷ 乾き側） | ≤ 0.45 | ≤ 0.45 |
| 段階の単調性 | level 4→3→2→1→0 で \|ΔL\| と地合いの比が単調に戻ること | 同左 |
| 乾燥後（60s 後） | \|ΔL\| ≤ 0.003、地合いの比 ≥ 0.9（完全に戻る） | 同左 |

- 比較の基準: v0.54.1（質感・染みなし）で同じ手順を撮り、文字色だけのときの「濡れと乾きの差」（文字の画素の平均 ΔL）と並べて記録する。ダークで、染みによる背景の差が文字色の差に加わったことを示す。
- 輪郭: 染み片の端から外へ r の範囲で、ΔL が単調に 0 へ落ちること（段差が 1 段で 0.01 を超えないこと）。
- 利用者の主観確認: ダークで「乾いていく様子が分かるか」を A/B（v0.54.1 との比較）で聞き、結果を記録する。数値の基準を満たしても、利用者が「見えない」と答えた場合は受入に進めず、強さの再調整に戻す。

### P3: 任意の発展（個別に Issue 化する）

- 表の行への染み（`table_row_element` の断片ごと）。
- 質感の種類の追加（`paper_texture_kind`）: 和紙（ライトは長い繊維、ダークは暗い繊維の黒和紙）。周期の異なる二層による繰り返し解消。
- `DARK_DELTA_L_FACTOR` の再調整（U-6）。
- 「時間帯の光」: 編集面に、ごく弱い縦方向の `linear_gradient` を重ね、時刻で色温度を変える。更新は時間単位で、新しいタイマーは既存の考え方（次の変化時刻まで眠る）に合わせる。
- 罫線紙: 見出しなどで行高が行ごとに変わるため、罫線と行が揃わない。行高が均一なプレーンテキストモードに限る場合だけ検討する。
- OS の「透明度を下げる」設定の読み取り。

## 7. 実装着手時の確認事項（spike）

設計の前提のうち、今回の環境で 0.3.6 のソースを読めず、0.2.2 の履歴版でしか確認できなかったもの:

1. `Window::paint_image` のシグネチャと、bounds の切り捨て・切り上げ。
2. `RenderImage::new` と画素並び（BGRA、premultiplied の有無）。
3. `Window::paint_shadows`（または Styled の box shadow）が、背景のない要素の**内側も**ぼかした色で塗るか。
4. atlas が画像 ID をキーにしていて、再アップロードしないこと。

3 が成り立たない場合、P2 の輪郭は §3.2.5 の代替 2（段付き角丸の `paint_quad`）とする。結果は P1 の PR に記録する。

## 8. 未決事項（利用者が決める点）

**U-1. 質感を既定でオンにするか**
推奨: **P1 では既定オフ（明示的に有効化）、P2 の GUI 受入後に既定オンへ切り替えるかを改めて決める。**
理由: 全利用者の見た目が更新だけで変わる。P1 単体では乾きの可視性という目的への効果を測れず、染みと組になって初めて価値を判定できる。

**U-2. 質感の種類（ライト・ダークの方向性）**
推奨: **ライトは上質紙（淡い繊維＋むら）、ダークは土壁・漆喰（暗い向きのむら＋細粒）。和紙は P3。**
理由: ダークで明るい繊維や粒を使うと、画面の埃や傷に見える。暗い繊維は暗い地の上では見えない。むら主体なら、ダークでも「地合いの消失」が知覚できる。

**U-3. 染みと帯の関係**
推奨: **統合（染みが有効なら、帯は染みと同じ層・色・柔らかさで α を上乗せ。染みが無効なら現行の帯のまま）。**
理由: 置き換えると「書き終えた」区切りの合図が失われる。併存させると、硬い縁と柔らかい縁が混在し、ダークでは向きが逆になる。統合なら台帳もタイマーも変えずに済む。

**U-4. 質感の適用範囲**
推奨: **`#editor-body` 全体（左右の余白を含む）。サイドバーや chrome には敷かない。**
理由: テキスト列だけに敷くと、列の端に見えない境界線ができる。chrome まで敷くと、道具と紙の区別がなくなり、うるさくなる。

**U-5. ダークで染みを暗くするか、明るくするか（艶）**
推奨: **暗くする。**
理由: 濡れた壁やコンクリートが暗く沈む見え方は日常的に知られている。暗くするとダークの文字とのコントラストが上がり、可読性の予算を消費しない。明るくする（艶）案は、平らな面の上では「帯」や選択と見分けにくい。

**U-6. 染みの導入後に、ダークの文字の明度シフト（現在 ×2）を下げるか**
推奨: **P2 では据え置く。P2 の GUI 測定でダークの基準を満たしたら、別 PR で ×1.5 に下げることを検討する。**
理由: 一度に二つを動かすと効果を切り分けられない。染みで背景が沈むと、×2 の文字は相対的に光って見えやすくなる。

**U-7. 質感がスクロールに追従するか、固定か**
推奨: **追従する（紙が文書と一緒に動く）。**
理由: 固定すると、文字が地合いの上を滑って泳ぐように見える。描画コストは同じ（毎フレーム全体を描き直すため）。

**U-8. 染みの強さを独立した設定にするか**
推奨: **独立させず、`drying_ink_strength` に連動させる。**
理由: 乾くインクの「強さ」という一つの概念で、文字・帯・染みをまとめて調整できるほうが分かりやすい。設定の数も増えない。独立した調整が必要だという声が出てから追加しても、保存形式の互換性は保てる。

**U-9. 質感の強さの段階数**
推奨: **弱・標準・強の3段**（乾くインクの設定と揃える）。
理由: 連続値のスライダーにすると、§3.1.3 / §3.2.4 のコントラスト下限を全域でテストする必要がある。3段なら全組み合わせを表で固定できる。
