# Issue #729 P1 実装ハンドオフ

このドキュメントは実装準備のための文書であり、**コードはまだ未実装・未検証**です。
設計の正本は `docs/implementation/issue-729-fence-up-design.md`（行番号は設計時点の base のものなので、現在のコードではシンボル名で探すこと）。

## 実装内容

↑↓の移動先選択で、現在の開示状態で非表示・高さ0のフェンス行を飛ばし、隣の表示行へ移動するようにする。開示されているフェンス行は移動元・移動先の両方になれる。`SourceMap` の `Bias` 意味論は変更しない。

変更箇所の中心:

- `crates/presentation/src/layout.rs` の `vertical_target`: 高さ0の構造行を移動候補から除外する（`LayoutLine` 自体は削除しない）。表セル内の断片移動は維持する
- `crates/ui/src/view.rs` の `layout_around`、`neighbor_block_window`、`target_in_neighbor`: 隣接ブロックの端が非表示フェンスなら表示行まで窓を進め、表示行のない空ブロックなら次のブロックへ進む。部分窓の前後1行が高さ0の行だけでも次の表示行を取得する
- 文書端（隣接行が存在しない）と解決失敗（レイアウト取得・位置解決の失敗）を区別し、既存の `None` によるフォールバック契約を保持する
- フェンスらしい文字列を UI で独自判定せず、既存の正式な投影情報を使う

## 受入条件

### 基本例（フェンス非開示、折り返しのない幅）

文書を行で表す: `1: before` / `2: ``` ` / `3: abc` / `4: ``` ` / `5: （空行）` / `6: after`

- (5,0) ↑ → (3,0)。(3,0) ↓ → (5,0)。(1,0) ↓ → (3,0)。(3,0) ↑ → (1,0)
- (6,0) ↑ → (5,0)（実在する空行は飛ばさない）
- 閉じフェンス後の行に本文がある場合も、↑は最後のコード表示行へ移る。コード本文が折り返されていれば、その最後の折り返し行が対象

### 最小報告例

- `"```\nabc\n```\n"`、キャレット12（末尾空行の先頭）で ↑ → オフセット4（`abc` の先頭）。↓ で12に戻る

### フェンス自体にキャレットがある場合（対象フェンスだけが開示された状態）

- 閉じフェンス (4,1) ↑ → コード (3,1)。閉じフェンス (4,1) ↓ → 空行 (5,0)（目標Xは保持）
- 開きフェンス (2,1) ↓ → コード (3,1)。開きフェンス (2,1) ↑ → 前行の同じ表示Xに最も近い位置
- 到着位置は表示X基準で、短い行では行末にクランプし、連続した↑↓では目標Xを保持する

### 空ブロック・文書端・選択

- 開閉フェンスだけの空ブロックは、両方が非表示なら↑↓で飛ばす。コード本文中の空行は通常のコード表示行として停止先にする
- 文書先頭・末尾方向に表示行がなければ停止する（範囲外位置や循環探索を発生させない）
- Shift+↑↓も同じ停止先を使い、anchor を保持して active のみ動かす
- 移動後の開示・再レイアウトで、適用済みの文書位置を変更しない
