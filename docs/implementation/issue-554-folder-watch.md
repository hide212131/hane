## 目的

サイドパネルに表示する作業フォルダの一覧を、アプリ外からの変更に自動追従させる。Finder／エクスプローラー、他のアプリ、クラウド同期ソフトがローカルへ反映した変更を共通に扱う。

## 方針・範囲

- 通常はmacOSのFSEvents、WindowsのReadDirectoryChangesWなどOSのイベント通知を使う。Rustの既存ライブラリによる抽象化を利用できる。常時の定期的なフォルダ走査を通常経路にしない。
- 通知は変更の手掛かりとして扱い、短時間集約して影響範囲の一覧・必要なメタデータを背景で再確認する。連続変更時も更新が永久に先延ばしにならないようにする。
- 監視開始と初期走査の間の変更、重複通知、通知欠落・overflow、監視先の消失や監視エラーを扱う。必要時の再走査・再接続は許容する。通知非対応環境の一般的なpolling fallbackは今回の必須範囲にしない。失敗を無言で正常扱いしない。
- 作業フォルダ切替・ウインドウ終了で監視を解除し、旧フォルダの通知・走査結果を新しいフォルダに適用しない。
- 一覧のためにファイル本文を開かない。クラウド上の本文ダウンロードを一覧更新が誘発しない。

## 受入条件

- [ ] macOS／Windowsの通常ローカルフォルダで、外部からのファイル・フォルダ追加／削除／名前変更／移動が、再起動・フォルダ再選択・Haneへのフォーカス復帰操作なしで一覧へ反映される。ネストしたフォルダも対象。
- [ ] 外部編集による更新日時の変更が、既存の並び順・表示規則へ反映される。既存のファイル種別フィルタ等を維持する。
- [ ] 通常の単発変更はOS通知受信から概ね1秒以内を目標として反映し、テストでは待ち時間上限を明示する。OS自体の通知遅延は区別して記録する。
- [ ] 通知が集中してもUIをブロックせず、変更終了後に実際の一覧へ収束する。変更がない間の定期的な全走査を行わない。
- [ ] 存在する項目の展開状態・選択・フィルタ・スクロール位置を可能な限り保持し、削除された項目の状態を安全に整理する。更新で本文のフォーカスを奪わない。
- [ ] 開いている本文・未保存編集・undo/redoを一覧更新で上書きしない。本文の自動リロードは追加しない。
- [ ] 監視の寿命、フォルダ切替後の旧通知／遅延結果拒否、通知欠落時の再走査、エラー時の安全な扱いを回帰テストで確認する。
- [ ] macOS／Windowsのbuild・関連テスト・lint、および通常ローカルフォルダを使うfocused GUIで外部追加／改名／削除、ネスト、UI状態と未保存本文保護を確認し、対象SHAと結果を残す。GUI操作経路はCommander PolicyとAGENTS.mdに従う。

## 対象外

OneDrive専用API・同期状態表示・同期制御・クラウド直接監視、OneDrive実機検証は不要（利用者指定）。本文の外部変更自動リロード、保存・命名規則の変更、全文検索結果の自動再検索、一般的なネットワークドライブ対応の拡張も含めない。
