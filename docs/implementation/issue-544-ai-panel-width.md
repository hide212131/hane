## 現状の証拠

`crates/ui/src/view/ai_selection.rs` の既存AI指示パネルは幅360px固定です。アンカーはウィンドウ内へスナップしますが、要素幅は縮まらないため、ウィンドウが狭いと右側の操作が表示範囲からはみ出します。Windows実機では編集欄幅279pxでフッタの単一入口からパネルが開くものの、送信ボタンは画面外にありマウス操作できませんでした。テスト用AI接続は未設定で、外部AI要求は送っていません。

## 今回の目的

利用可能な編集領域が狭い場合にもAI指示パネルをその範囲内へ収め、閉じる・入力・送信の各操作を表示してポインターとキーボードから操作できるようにします。通常幅での既存レイアウト、選択文、入力値、処理状態を維持します。これにより#536のF02を満たします。

## 実装範囲

- AI指示パネルの横位置と幅を、アンカー位置と現在の利用可能な編集領域の両方に合わせる。
- 279px、280px、および通常幅で、パネルと送信/閉じる操作が水平に切れないことを確認する。
- 狭幅の送信操作を、実際の外部AI要求を発生させないテスト手段で検証する。
- 本文選択、編集中の文書、未保存状態、保存プロンプト、キーボードフォーカス、日本語変換中の抑止を維持する。
- 必要な回帰テストを追加し、macOSとWindowsの直接GUI確認手順・結果を記録する。

## 対象外

AIサービス接続・送信処理、プロンプト形式や結果画面、本文編集/保存状態の仕様変更、#536のF02を狭めることは行いません。通常幅の見た目を変える全面再設計もしません。

## 検証条件

- 自動テストで279px/280px/通常幅のレイアウト境界と操作部品の可視範囲を確認する。
- 外部AIへの送信を行わず、狭幅でポインターとキーボードの操作経路を確認する。
- macOSおよびPapa-win上のWindows実画面で279px/280pxと通常幅を確認する。
- 本文選択、未保存内容、入力値、IME制御が維持されることを確認する。
- 必須CI、current-head review、対象head/baseに紐づくGUI証拠を揃える。
