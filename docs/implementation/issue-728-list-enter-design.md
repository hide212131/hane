# Issue #728 設計書ドラフト：リスト項目の左端と継続行での Enter

調査対象は `fe715608b131521c114446cab106cb41aa43b829`。ローカル HEAD と `origin/main` が一致することを確認した。コード・文書の変更、ビルド、テスト実行、GUIでの再現確認は行っていない。以下では、コードから確定できる結果と、表示についての推定を区別する。

## 1. 現行挙動の分析

### Enter の処理経路

| 層 | 現行処理と根拠 |
|---|---|
| キー処理 | 本文の Enter は、IME・入力ガードを確認して `apply_list_edit_intent(Enter)` を呼ぶ。未処理なら通常改行へ進む。`crates/ui/src/actions.rs:359–390` |
| 編集用解析 | 文書の current revision に一致する index を使い、不一致なら作り直す。`crates/ui/src/view.rs:3601–3623` |
| 編集用 projection | キャレットを含むブロックを同期解析して `ListEditProjection` を構築する。背景の表示用解析を待たない。`crates/markdown/src/block_index.rs:1033–1048` |
| 計画 | `plan_list_edit` が置換範囲・置換バイト列・編集後の選択位置を返す。`crates/markdown/src/list_editing.rs:504–644` |
| 適用 | `replace_range_recorded` で計画を適用する。`crates/ui/src/view.rs:3625–3647` |
| 文書・履歴 | 文書を置換して選択位置を設定し、一つの undo 対象として記録する。`crates/editor/src/lib.rs:356–398` |
| 更新・表示 | `after_input` が index を局所更新し、背景解析・表示更新を進める。`crates/ui/src/view.rs:2611–2655` |
| 表示投影・配置 | ソースからマーカーと行の所属を投影し、レイアウトがリストの深さ・マーカー幅を配置に反映する。`crates/presentation/src/projection/mod.rs:1110–1169, 2032–2082`、`crates/presentation/src/layout.rs:1603–1698` |

通常改行への fallback は `EditorCommand::Insert("\n")` であり、自動インデントを追加しない。`crates/ui/src/view.rs:3652–3660`。

### ケース1：リスト項目の左端

入力を `"- abc"`、キャレットをソース offset `0` とする。

1. `item_at(0)` は当該項目を返す。検索条件にマーカーの左端を除外する条件はない。  
   根拠：`crates/markdown/src/list_editing.rs:113–129`
2. `on_opening_line` は真になる。本文より前かどうかは判定しない。  
   根拠：同 `518–521`
3. 本文 `"abc"` は空でないため、空項目の exit 分岐を通らない。
4. 非空項目の Enter 分岐が `item_prefix` の `"- "` を使い、offset `0` に `"\n- "` を挿入する。  
   根拠：同 `589–642, 792–808`

したがって、**計画段階で次の誤った文書になる**。

```text
入力バイト列       "- abc"
置換範囲           0..0
挿入バイト列       "\n- "
結果バイト列       "\n- - abc"
編集後キャレット   3（元からある '-' の直前）
```

結果の全バイトは次のとおり。

```text
0A 2D 20 2D 20 61 62 63
```

これは「計画は正しいが表示だけ崩れる」問題ではない。既存のマーカーを右側に残したまま新しいマーカーを挿入している。

`"- - abc"` は入れ子のリストとして解釈され得る。表示側は、編集中のマーカーを実ソースとして開示し、非編集中には合成したマーカーを表示する。また、リストの深さを配置に反映する。根拠：`crates/presentation/src/projection/mod.rs:1110–1169`、`crates/presentation/src/layout.rs:1600–1601, 1676–1698`。

このため、報告の `  - - abc` は、**ソース `"\n- - abc"` に表示上のインデントが加わった状態**と整合する。ただし、報告画面そのものは未検証である。指定された入力と offset `0` から、先頭に実スペース2個を持つ `"  - - abc"` が直接生成されるわけではない。

### ケース2：継続行

編集用 metadata の `body_range` は、項目全体の本文ではなく、**項目の先頭物理行の本文範囲**である。`item_range` は継続行や子要素を含み得る。

根拠：`crates/markdown/src/list_editing.rs:159–208, 215–225`。

現行のリスト専用 Enter は、先頭物理行以外では `NotApplicable` を返す。Shift+Enter も同じ制限を持つ。

根拠：同 `577–587, 632–634`。

そのため、例えば次のようになる。`▮` はキャレットを示し、文書の一部ではない。

| 入力 | 現行の Enter 後 |
|---|---|
| `"- abc\n  def▮"` | `"- abc\n  def\n▮"` |
| `"- abc\n  de▮f"` | `"- abc\n  de\n▮f"` |
| `"- abc\n▮"` | `"- abc\n\n▮"` |

最後の例では、末尾改行直後のキャレットを元の項目が所有しない場合もある。`item_at` は「項目の終端改行の直後」を意図的に除外している。根拠：同 `119–127`。

一方、表示側は先頭マーカーのない項目内の行を `Continuation` 等として扱う。必要な構造インデントを隠し、レイアウトで本文位置を確保するため、**画面で右に見えることと、実スペースが存在することは同義ではない**。

根拠：

- `crates/markdown/src/markers.rs:801–819, 899–910`
- `crates/presentation/src/projection/mod.rs:1189–1194, 2064–2082`
- `crates/presentation/src/layout.rs:1656–1698`

また、インデントのない本文も CommonMark の lazy continuation として直前のリスト項目に含まれ得る。既存の空項目 exit は、これを防ぐため必要な空行境界を作っている。根拠：`crates/markdown/src/list_editing.rs:700–749`。

## 2. 確定する意味

### 採用する解釈

本ドラフトでは、オーナーの3分類を次の操作規則として採用する。

> Enter 時に、ソース上の行頭の記述とキャレット位置から、分割後の行に置く改行・インデント・マーカーを決める。

新しい Markdown 文法は導入しない。既存行の所属は通常の parser に委ね、Enter が必要なソース編集を行う。画面の自動折り返しは「2行目以降」に含めない。

「カーソル位置」には次の解釈がある。

| 解釈 | 判断 |
|---|---|
| 画面上の x 座標だけで所属を変える | 表示上のインデント・折り返し・マーカー開示に左右されるため採用しない |
| ソース上の位置と行頭記述から Enter の編集内容を決める | **推奨・本ドラフトで採用** |
| 通常の文字入力でも既存行を遡及的に再構成する | Enter の修正を超えるため対象外 |

以下の例は LF。文字列中の `\n` は実際の改行を表す。

### ケース1：マーカーの左に空行を入れる

```text
入力   "▮- abc"
出力   "\n▮- abc"
```

- 文書：`"- abc"` → `"\n- abc"`
- キャレット：`0` → `1`
- 元の項目のバイト列は変えない。
- 新しい項目マーカーを生成しない。
- キャレットは、通常の Enter と同様に、元の項目が移動した行の先頭に置く。

順序付き・タスクでも同じ規則とする。

```text
"▮10. abc"   → "\n▮10. abc"
"▮- [x] abc" → "\n▮- [x] abc"
```

ネスト項目では元のインデントも保存する。

```text
"- parent\n  ▮- child"
→
"- parent\n\n  ▮- child"
```

これは項目を outdent する操作ではない。

### ケース2-1：インデントもマーカーもない左端は、リスト外へ進む

```text
入力   "- abc\n▮"
出力   "- abc\n\n▮"
```

- キャレット：`6` → `7`
- 続けて `def` を入力した文書は `"- abc\n\ndef"`。
- `def` はリスト外の段落になる。

既存の lazy continuation の先頭でも、Enter により境界を作る。

```text
入力   "- abc\n▮def"
出力   "- abc\n\n▮def"
```

後続の文字列を削除せず、外側の段落として分離する。

ただし、**すでにインデントを持つ既存行の、その空白より前へキャレットを移動しただけでは、空白を削除して外側へ変換しない**。

```text
入力   "- abc\n▮  def"
出力   "- abc\n\n▮  def"
```

右側の `  def` は引き続き元の項目に属し得る。外側へ進む分類は「インデントもマーカーもない左端」に適用する。これにより、Enter が既存のインデントや後続要素を暗黙に破壊することを避ける。

### ケース2-2：本文用のインデントがあれば、同じ項目を続ける

通常の `- ` 項目では次のとおり。

```text
入力   "- abc\n  def▮"
出力   "- abc\n  def\n  ▮"
```

- キャレット：`11` → `14`
- 新しい `- ` は追加しない。
- 続けて入力した本文は同じ項目に属する。

途中で分割する場合も、右側の本文とインデントを維持する。

```text
入力   "- abc\n  de▮f"
出力   "- abc\n  de\n  ▮f"
```

空白だけの継続行でも同様とする。

```text
入力   "- abc\n  ▮"
出力   "- abc\n  \n  ▮"
```

「2スペース以上」は通常の `- ` の例であり、全リスト共通の固定幅にはしない。

```text
"10. abc\n    def▮"
→ "10. abc\n    def\n    ▮"

"- parent\n  - abc\n    def▮"
→ "- parent\n  - abc\n    def\n    ▮"
```

既存の継続行では、parser が確認した項目所属と構造インデントを使い、実際の行頭空白を維持する。タスクの `[x]` は構造上のマーカー幅と本文の表示位置を異ならせるため、`body_indent_columns` を継続行の必須最小幅として一律適用しない。

### ケース2-3：明示的なマーカーは別項目

`-` と空白を持つ行は、前項目の継続本文ではなく、parser が認める新しいリスト項目として扱う。

```text
入力   "- abc\n- def▮"
出力   "- abc\n- def\n- ▮"
```

入力時点で `def` は次の項目であり、その Enter はさらに次の項目を作る。`+ `、`* `、順序付きマーカーにも既存規則を適用する。

**空項目の Enter は既存の exit を優先する。**

```text
入力   "- abc\n- ▮"
出力   "- abc\n\n▮"
```

したがって「`- ` なら次項目」は、その行の役割を示す分類であり、空項目で Enter を押しても無限に項目を増やす意味ではない。

先頭行の本文途中での既存動作も維持する。

```text
"- ab▮c" → "- ab\n- ▮c"
```

## 3. 実装方針

### 変更する層

中心は `crates/markdown/src/list_editing.rs` とする。必要な現在文脈の取得を `crates/markdown/src/block_index.rs` で補う。

UI にリストの意味判断を追加せず、既存の `MarkdownEditPlan` → `replace_range_recorded` 経路を維持する。表示を補正するための仮想マーカーや一時的なリスト状態は追加しない。

これは `docs/adr/0029-source-first-list-editing.md:63–92` の責務分離に従う。

### 分岐の変更

Enter の判定順序を次のようにする。Backspace と共有する空項目 exit の条件は維持する。

1. **選択範囲・保護対象の確認**
   - 選択範囲がある場合は既存の通常編集へ戻す。
   - 引用・コード等を継続段落と誤認しない。
2. **項目のマーカーより前**
   - 同階層マーカーを生成する分岐から除外する。
   - 行頭からキャレットまでが項目の先行インデントなら、そのバイト列を保持して項目の上へ空行を挿入する。
   - マーカー内部やタスク接頭辞内部は通常編集へ戻す。
3. **先頭行の空項目**
   - exact body-start、信頼性、保護条件を使う既存 exit を維持する。
4. **先頭行の非空本文**
   - 既存の同階層項目分割を維持する。
5. **継続物理行**
   - 明示マーカー行は当該項目の先頭行として扱う。
   - インデントを持つ継続段落では、改行と継続用空白を挿入する。
   - インデントもマーカーもない行頭では、必要な空行境界を作る。
   - 判定できない位置では通常編集へ戻す。

本文継続の判定には、現在の projection に「物理行・段落所属・構造インデント」を持たせる。既存の parser tree と `list_structural_prefixes` を利用し、正規表現だけで所有者を推測しない。

`body_indent_columns` は先頭行の Shift+Enter が生成する本文位置として引き続き利用できるが、構造上の最小インデントとは区別する。

### 末尾空行の文脈

`"- abc\n▮"` や `"- abc\n  ▮"` は、`item_at` だけでは所有者が得られない場合がある。

`item_at` の範囲を広げて通常段落まで前項目に所属させる変更は行わない。編集用 projection に、**直前の確認済み項目に隣接する空白行の編集文脈**を別途持たせる。

- current revision のソースから取得する。
- 非空の別ブロック、引用、コード等を越えて所有者を探索しない。
- 空白行が別ブロックに属する場合だけ、隣接する直前ブロックを追加確認する。
- 表示用 `ListProjection` の到着には依存しない。

### Shift+Enter

先頭行では既存の「同じ項目の本文を続ける」動作を維持する。継続段落でも継続用インデントを維持できるようにする。左端や接頭辞内部にマーカー・本文用空白を誤挿入しないよう、Enter と物理行の分類を共有する。

### Issue #714 との関係

**同じ対象分岐に触れる。独立したファイル変更とは扱えない。**

#714 の本命は `crates/markdown/src/list_editing.rs:636` の `"\n"` 固定挿入であり、#728 はその手前に位置判定を追加し、継続行向けの改行挿入も追加する。Shift+Enter の同種箇所は同 `581` にある。

改行選択は共通化し、次を推奨する。

1. 分割対象行に終端子があれば、それを使う。
2. EOF 行なら、近接する既存の終端子を使う。
3. 改行のない文書では既定値として LF を使う。
4. 既存の終端子を分断・正規化しない。

#714 を先行させ、受け入れ済みの改行選択処理を #728 から使う進め方を推奨する。逆順の場合も、#728 に LF 固定の新経路を増やさないよう、共有部分の担当を調整する。

単にケース1を `NotApplicable` にするだけでは、UI fallback が LF 固定のため、CRLF の問題を残す。

## 4. 影響範囲と回帰リスク

| 対象 | 維持する契約・主なリスク |
|---|---|
| 順序付きリスト | 左端では元の番号・区切り文字を保存する。本文分割では既存の意味上の次番号を使う。後続番号の一括書換えは追加しない |
| タスクリスト | 左端ではチェック状態を保存する。新項目は未チェック。継続本文にはチェックボックスを追加しない |
| ネスト | 子項目の所属と既存インデントを保存する。本文継続で新しい子・兄弟項目を作らない |
| 空項目 | トップレベル exit、ネストの一段 outdent、引用等の保護条件を維持する |
| 項目途中 | 右側本文・子要素を欠落させない。今回の修正で子要素の再配置規則を追加しない |
| 通常段落・コード | `- ` に見える文字列だけでリスト操作を開始しない |
| 改行コード | LF／CRLF／混在で新たな意図しない混在や CRLF の分断を起こさない |
| 表示・キャレット | ソース offset、開示後の表示位置、クリック位置、入力位置を一致させる |

既存の空項目保護条件は `crates/markdown/src/list_editing.rs:647–697` にある。これを継続行の追加によって迂回しない。

本文の欠落・重複、意図しないインデント削除、別項目への誤入力、UTF-8／CRLF の途中へのキャレット配置、undo による不完全復元は、**エディタコアの blocker** とする。

ケース1の表示には計画の誤りで説明できる原因があるため、最初からレイアウトを変更しない。正しいソースを生成しても表示・入力位置が一致しない場合は、その事実を別途切り分ける。

## 5. テスト計画

### 計画単体：`crates/markdown/src/list_editing.rs`

既存の `replacement` helper（`834–845`）を利用し、最終文書とキャレット offset を検証する。重要な例では置換範囲・置換バイト列も確認する。

- ケース1：`"- abc"` の offset `0` → `"\n- abc"`、offset `1`。
- `-`／`+`／`*`、順序付き `.`／`)`、チェック済み・未チェックの左端。
- ネスト項目の行頭・マーカー直前と、接頭辞内部の通常編集。
- ケース2の3分類について、第2節の全例。
- 継続行の本文先頭・途中・末尾、空白だけの行、3行目以降。
- 2スペース以外のインデント、タブ、複数桁番号、タスク、ネスト。
- 空項目の既存 exit／outdent／保護条件。
- マーカーに似た通常本文、引用、fenced／indented code。
- 日本語・絵文字を含む本文と、有効な UTF-8 境界の選択位置。
- LF／CRLF／混在／終端改行なし。
- 再解析した tree でも、外側段落・同じ項目・兄弟項目という期待した所属になること。

既存の関連テストは同 `849–987`。空項目・引用・raw recovery のテストも回帰対象とする。

### 編集文脈：`crates/markdown/src/block_index.rs`

実際の `BlockIndex::list_edit_projection_at` を通す。

- 項目末尾改行の直後、EOF 空行、空白だけの末尾行。
- 継続行がブロック境界にある場合。
- 文書先頭以外にあるリストの絶対 offset。
- 編集直後の index と背景解析後の index。
- 隣接する通常段落・コードから前のリストを誤取得しないこと。

### UI 統合：`crates/ui/src/view.rs`

既存の source-first リスト編集テスト群（`11674` 以降）に追加する。

- 実際の Enter action から計画・適用まで通したケース1と3分類。
- Shift+Enter の継続動作。
- Enter → 文字入力を、背景解析を待たず連続実行。
- 1回の undo で Enter 前の文書・選択位置へ戻り、redo で完全復元。
- 選択範囲・IME・編集不可状態の既存入力制御。
- CRLF 文書で左端挿入・項目分割・継続・exit を連続実行。

### 表示・入力位置：`crates/presentation/src/projection/tests.rs`

正しい編集後ソースを表示し、次を検証する。

- 空行が消えず、マーカーが重複しない。
- 継続行の owner が同じ項目で、独立マーカーを持たない。
- 外側段落にリストの配置が残らない。
- マーカー開示あり／なし、formal projection あり／なしでソース対応が一致する。
- `point_for_source` と hit-test の往復が一致する。
- 自動折り返しを物理的な継続行と混同しない。

実装後は対象 head の Debug／development build で、マーカー左への移動、Enter、続けて入力、undo／redo、再読み込みを focused GUI scenario として確認する。表示だけでなく保存されたソースも照合する。
