# Issue #757 実装設計書 — Markdown 文書内の HTML タグ表示

> 司令塔注記: 概要にある「Jev は認証設定を利用できず」は、設計実行時の読み取り専用サンドボックスがソケットを遮断したことによる見かけ上の制約であり、Jev 自体は正常に利用できる。また「Issue 本文は提示された本文を採用した」は起票内容そのものであり、内容の齟齬はない。設計の判断内容はそのまま有効とする。

## 概要

Hane の通常表示と閲覧モードで、一部の HTML タグを既存の Markdown 装飾、リンク、ブロック表示に写像する。文書の原文は引き続き唯一の編集対象とし、タグの非表示や開示は表示上の操作として扱う。既存の Markdown と等価な要素には、同じスタイル、レイアウト、リンク操作を使う。

GFM の raw HTML 構文を認識範囲の参考にする。GFM の `tagfilter` と GitHub.com の追加サニタイズは別の処理であり、Hane の対応範囲は下表で定義する。基準は指定された main の `411c8089`。GitHub 上の Issue 本文と関連 PR の最新状態は取得できなかったため、Issue の要件は提示された本文を採用した。Jev は認証設定を利用できず、設計判断は基準コードと提示された受入条件に基づく。実装は設計承認後に開始する。[GFM 仕様](https://github.github.com/gfm/)

## タグ対応表

「タグ全体」は、`<` から `>` までの開始タグ・終了タグの各範囲を指す。属性、引用符、タグ内の空白も含む。表中の非表示は通常編集時の非開示状態と閲覧モードに適用する。

| タグ | フェーズ | 隠すソースバイト | 表示・ブロックの扱い |
|---|---:|---|---|
| `b`、`strong` | 1 | 開始・終了タグ全体 | `StyleKind::Bold`。`**…**` と同じ表示 |
| `i`、`em` | 1 | 開始・終了タグ全体 | `StyleKind::Italic`。`*…*` と同じ表示 |
| `s`、`del`、`strike` | 1 | 開始・終了タグ全体 | `StyleKind::Strikethrough`。`~~…~~` と同じ表示 |
| `code` | 1 | 開始・終了タグ全体 | 内容をリテラルとして `StyleKind::InlineCode` で表示。ソースの空白を保持し、内容中の装飾やリンクを抑止 |
| `a` | 1 | 有効なリンクを作れた場合、開始・終了タグ全体 | `StyleKind::Link` と既存の外部リンク操作を再利用。検証済みの絶対 `http` / `https` URL を持つ `href` を受理。無効な `href` や空のラベルは原文表示 |
| `p` | 2 | 開始・終了タグ全体 | 単独のソース行を占める要素を `BlockKind::Paragraph` に写像 |
| `h1`〜`h6` | 2 | 開始・終了タグ全体 | 単独のソース行を占める要素を段階に対応する見出し表示に写像。既存 Markdown 見出しと同じレイアウト |
| `hr` | 2 | 単独行のタグ全体。行内の前後の空白は既存区切り線と同じ扱い | `<hr>` と `<hr />` を `BlockKind::Rule` に写像。ソース行末は保持し、区切り線と原文の切り替えに既存の行描画を使う |
| `img`、`br` | 対象外 | なし | 原文表示。画像取得や、ソース改行に対応しない表示行の生成は行わない |
| `u`、`sub`、`sup`、`kbd` | 対象外 | なし | 原文表示。下線の意味付け、ベースライン移動、キーキャップ表示は別の表示契約を要する |
| `details`、`summary`、`div`、`span` | 対象外 | なし | 原文表示。折りたたみ状態、汎用コンテナ、属性由来の表示は導入しない |
| `blockquote`、`ul`、`ol`、`li`、`pre` | 対象外 | なし | 原文表示。複数行のレイアウト、リスト編集、コードブロックの契約は既存 Markdown 記法で利用できる |
| `table`、`thead`、`tbody`、`tfoot`、`tr`、`th`、`td` など | 対象外 | なし | 原文表示。HTML のセル結合、列幅、行とセルの位置対応は扱わない |

フェーズ1の対応位置は、トップレベルの Markdown 段落・見出し内で、開始タグと終了タグが同じ物理行・同じインライン構文スコープにある場合とする。対応タグ同士は正しく閉じた入れ子を受理し、通常の Markdown 装飾とも合成する。タグが Markdown の構文境界をまたぐ形、リスト・引用・表セル内、複数行にまたがるペアは対象外とする。リンクの入れ子や Markdown 画像を含む `a` は原文表示とし、有効な `a` のラベル内に競合する裸 URL のリンクを作らない。

フェーズ2は、トップレベルの `HtmlBlock` の実体が、一つの完全な対応要素と前後の空白で構成される単一行に限る。`p` と見出しの内容にはフェーズ1の対応タグを使用できる。`HtmlBlock` の内容は Markdown として再解析しないため、`<p>**原文**</p>` の `**` はそのまま見える。

## 振る舞いと理由

- **通常編集**。インラインは Markdown マーカーと同じ開示モデルを使う。カーソル、選択、IME の合成範囲、現在の検索一致が要素の範囲に触れたとき、所有する開始・終了タグを原文で開示する。入れ子では接触した要素とその祖先が開き、隣接する兄弟の境界では既存のカーソル親和性で所有側を決める。タグを開示した状態でも、リンクの操作対象は表示ラベルに限る。
- **単一行ブロック**。カーソル等がブロックの内容行に触れたら、そのソース行全体を編集可能な原文表示に戻す。`p`・見出し内の子タグもまとめて開示する。Front Matter と同じく行描画と高さキャッシュを同期させる。判定には要素の実体行を使い、索引が同じブロックに含める後続空行は開示範囲から除く。
- **閲覧モード**。対応タグは常に非表示とし、選択や検索は表示内容にマッピングする。隠れたタグ内だけにヒットした場合は、検索移動先を既存のソース位置に対応する行境界に置く。編集を再開すると、その位置で通常の開示判定を行う。コピーは既存の選択ソース範囲を使い、範囲内の非表示バイトも含む。
- **プレーンモード**。編集・閲覧の設定にかかわらずタグをソースのまま表示し、シンタックスハイライト設定に従う。HTML 由来のスタイルやリンク操作は作らない。
- **原文と位置**。`SourceMap` にタグの半開バイト範囲と開閉方向を保持し、`HiddenMarkup` と `ExpandedMarkup` を切り替える。選択、コピー、検索、IME、保存は原文の座標を使う。表示の開閉、モード切替、検索移動で、ソースバイト、リビジョン、dirty、undo／redo 履歴は変化しない。実際の入力だけが通常の編集履歴に入る。

未対応タグ、コメント、未知のタグ、不整合なタグはソース表示にフォールバックする。対応構文の認識に失敗した要素から、一部のタグだけを隠したり、リンクだけを作ったりすることは避ける。属性は `a` の `href` のみ表示機能に使用する。`class`、`style`、`id`、`onclick` などは効力を持たず、原文の開示・プレーン表示・コピーで確認できる。

## セキュリティの判断

- HTML 由来の機能は許可リストで決める。`script`、`style`、`iframe`、`form`、埋め込み要素などはリテラルとして扱い、HTML の実行、CSS、フォーム制御、イベント属性を表示系へ渡さない。走査がその範囲を所有する間は、内側から対応 HTML のリンクや装飾を作らない。危険な生 HTML ブロックや `code` のリテラル領域を表示用に切り出す場合も、本文を独立した Markdown として誤認し、画像・リンクを生成する経路を塞ぐ。
- `href` は属性値を一度だけデコードして検証する。`is_external_http_url` の既存条件に加え、HTML 由来の値は URL として構文解析できることと、ホストがあることを確認する。空白・制御文字、重複 `href`、空値、相対 URL、`//` で始まる URL、`javascript:`・`data:`・`file:` などは拒否する。表示中の先読みは行わず、既存の明示的なリンク操作でのみ開く。リンク先とスタイルは同じ検証結果から作る。
- `img` は対象外とし、HTML 由来の画像取得、リモートフォントやその他のリソース取得を追加しない。既存 Markdown 画像の取得条件を維持する。
- 走査は前進する字句走査と深さ制限付きスタックで行う。初期上限はタグ当たり 4 KiB、認識単位当たり 64 KiB・256 タグ、入れ子 16 段とする。引用符内の `>` はタグ終端に数えない。上限超過や構文エラーでは、その認識単位の HTML 表示データを破棄し、元のバイト列を表示する。ビューポートの行描画ごとに元のブロックを再走査しない。

## パーサ・索引と変更予定ファイル

pulldown-cmark の構文木とソース範囲を正本とする。インラインでは `InlineHtml` のイベント範囲だけをタグ候補に使い、同じスコープ内でタグ名を ASCII 大文字小文字非区別で対応付ける。`<b>…</strong>` のような異名の組、閉じ忘れ、交差、対応する終了タグのない自己閉じ形式は原文表示とする。エスケープされたタグ、Markdown コード内、Front Matter 内の文字列はタグ候補に含めない。ブロックでは、pulldown-cmark が確定した `HtmlBlock` 範囲の内側だけを走査する。本文の文字参照の展開や空白の正規化は対象外とし、本文のソース対応を保つ。

| 相対パス | シンボルと変更内容 |
|---|---|
| `crates/markdown/src/html.rs`（新規） | 許可タグの字句走査、開始・終了タグの対応付け、`href` の検証を実装する。要素範囲、内容範囲、タグ範囲、表示種別を返す |
| `crates/markdown/src/parser.rs`、`crates/markdown/src/syntax.rs` | `build_tree` の結果を使い、`parse_document_with_front_matter` が `MarkdownParse` に検証済みの HTML 表示情報を付加する。`NodeKind::Html`・`InlineHtml`・`HtmlBlock` と `parser_options` は維持する。`is_external_http_url` を内部共有し、HTML のリンクと既存リンクの範囲競合を解決する |
| `crates/markdown/src/markers.rs` | `derive_markers` の Markdown マーカー抽出を再利用する。HTML の開始・終了マーカーは所有範囲と開閉方向を持つ解析結果から投影し、隣接タグが一つの無方向マーカーに併合されないようにする |
| `crates/markdown/src/block_index.rs`、`crates/markdown/src/local_block_index.rs` | `BlockIndex::update` と `local_block_index` が同じ認識結果を使えるようにする。フェーズ2では、行表示と初期高さに必要な単独ブロックの種別・範囲を保持する。範囲はブロック相対で保持し、既存の増分再解析・置換と一緒に更新する |
| `crates/presentation/src/display.rs`、`crates/presentation/src/projection/mod.rs` | `syntax_display` の既存 `StyleKind`・`BlockKind` を再利用する。`ProjectionIndex`、`present_markdown_from_parse`、`marker_is_disclosed`、`marker_edge` に検証済み HTML の範囲を接続する。`hr` は `present_rule_line` を使い、既存の `LinkTarget` に検証済みリンクを渡す |
| `crates/presentation/src/projection/block.rs`、`crates/presentation/src/source_map.rs` | `present_block`、`expected_disclosures`、`block_height_with_disclosure` が同じ認識・開示結果を使う。`SourceMap`、`Visibility`、`MarkerEdge` の既存の境界対応を使用する |
| `crates/ui/src/line.rs`、`crates/ui/src/view.rs`、`crates/ui/src/view/height_sync.rs`、`crates/ui/src/view/reading_mode.rs` | `presented_block` に開示状態を渡し、`disclosures_are_current` と高さ同期の判定を揃える。`link_destination_at` と `disclosure_policy` の既存経路を再利用する。プレーンの `projection/highlight.rs` は現行のソース表示を使う |

`IndexedBlock::line_count` は物理行数のままとする。フェーズ1で変わるのは表示幅と折り返し、フェーズ2で加わるのは見出し・区切り線・原文行の表示高の切り替えである。初期推定、増分更新、測定済みの高さで同じ表示種別を使い、開示前後でスクロールアンカーをソース位置に結び付ける。後続空行、CRLF、文末の空のカーソル行は既存の規則で数える。

タグの編集で Markdown のブロック境界が動いた場合は、既存の `BlockIndex::update` の再解析・フォールバックに従う。局所解析で所有ブロックやペアの完全性を確定できない間は原文表示とし、同一リビジョンの解析結果が届いた時点で更新する。画面外から始まる生 HTML の途中行を、独立した対応ブロックと推測しない。`#751` の開示と高さ同期、`#737`・`#738` のプレーン表示を利用する設計であり、基準コード上で全域リファクタリングへの依存は見込まない。実装着手時に current main と関連 PR の重複を確認し、既存の解析・表示経路で変更前測定を取る。

### 実機 GUI 確認

1. 対象コミットの Debug ビルドを隔離状態で起動し、SHA、実行バイナリの由来とパス、実 PID を記録する。macOS と Windows の対象環境で確認し、Windows は接続済みの Windows 側アプリから直接操作する。
2. 対応タグと等価な Markdown、非対応タグ、壊れたタグ、危険な `href`、非 ASCII 文字を一つのテスト文書に並べる。LF と CRLF のフィクスチャを用意し、保存前のバイト列を記録する。通常表示で装飾とブロックが一致し、原文表示へのフォールバックが機能することを確認する。
3. マウスと左右キーでタグ境界を往復し、選択、コピー、タグ属性への検索一致、ネイティブ IME の変換・取消を試す。狭いウィンドウで折り返しを発生させ、開示・閉鎖とモード切替後のカーソル、行高、スクロール位置を確認する。
4. 閲覧モードでタグが閉じたまま有効なリンクを操作できること、ドラッグが選択になることを確認する。プレーンモードで原文に戻し、HTML 由来の画像取得や無効リンクの起動がないことを確認する。リンク操作の確認には制御できる宛先を使う。
5. 閲覧・開示だけを行った文書を保存し、元のファイルとバイト列を比較する。続いて本文と属性を意図的に編集して保存し、差分が編集箇所だけに出ること、undo 後の保存で元のバイト列に戻ることを確認する。対象プロセスの終了を確認して隔離状態を片付ける。

## フェーズ分け

1. **フェーズ1 — インライン装飾とリンク**。`b` 系、`i` 系、`s` 系、`code`、`a` を導入する。3 モード、ソース位置とコピー、開示、リンク検証、壊れた入力のテストが通り、Debug の実機確認で表示・編集・保存の不変条件を満たした時点で完了とする。
2. **フェーズ2 — 単一行ブロック**。`p`、`h1`〜`h6`、`hr` を追加する。全体解析と増分解析の一致、行数・高さ・スクロールの整合、実機での表示切替と保存のバイト比較を完了条件とする。フェーズ1の挙動も再確認する。

## 対象外

表で対象外とした要素に加え、ブラウザ互換の HTML 解析やエラー回復、GitHub.com のサニタイズの完全再現、複数行 HTML のレイアウト、HTML の構造編集、貼り付け変換・保存形式の変更を対象外とする。
